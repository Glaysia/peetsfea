# peetsfea 0.2.20

Release Date: `2026-04-03`

## One-line Summary
- 0.2.20 is a stabilization release that keeps TX mode-0 builds alive when the direct bridge already exceeds the TX DD top contract, and exposes AEDT message-manager output through the runtime wrapper layer.

## Highlights
- Synced the public package/spec baseline, examples, fixtures, docs, and versioned run-output naming to `0.2.20`.
- `tx_mode0_rotation` now clamps to `0` degrees instead of raising immediately when a finalized TX-mode-0 candidate point is already above `tx_region_dd.top_z`.
- Added `Desktop.GetMessages(project_name, design_name, level)` to the repository AEDT protocol/wrapper/proxy stack, backed by PyAEDT `odesktop.GetMessages(...)`.
- Geometry teardown now logs AEDT message-manager lines in `finally`, so ValidateDesign and release-path failures keep the underlying AEDT error text in the repository logger.

## Breaking Changes / Migration
- Runtime now accepts only `spec_version == "0.2.20"`.
- Older `0.2.19` TOML files must be bumped to `0.2.20` before they will run under the current baseline.

## Public API / Interface Changes
- `SUPPORTED_SPEC_VERSION = "0.2.20"` is the current public baseline.
- The repository AEDT desktop wrapper now exposes:
  - `Desktop.GetMessages(project_name, design_name, level)`

## Runtime / Debug Notes
- TX mode-0 builds that previously failed at rotation-angle computation can now continue with `0`-degree rotation and fail later only if a downstream AEDT/design validation step still rejects the geometry.
- When AEDT itself reports geometry/design errors, the repository logger now emits the message-manager payload before desktop release.

## Validation
- Headless `entry/build.py` replay now completes past the former `000007_d161_847f_0` TX mode-0 rotation failure.
- Subsequent failing designs can now be diagnosed from logged AEDT message-manager output without relying only on GUI inspection.
