# peetsfea 0.2.17

Release Date: `2026-03-15`

## One-line Summary
- 0.2.17 adds a second TX vertical layout mode and redefines the public spec contract around `layout_mode + mode2 x-ratio`.

## Highlights
- Runtime, example spec, package version, and documentation baseline are bumped to `0.2.17`.
- Added sampled path `coil_placement.tx_vertical_layout_mode`. `1` keeps the legacy `ZX` mode and `2` enables the new `YZ` mode.
- Added sampled path `coil_spacing.tx_vertical_mode2_pair_spacing_ratio`. The default example range is `0.0..0.03`, `count=25`, and it owns the mode-2 internal pair gap relative to `tx.region.outer_h_mm`.
- Added sampled path `coil_placement.tx_vertical_mode2_x_ratio_to_tx_dd_center`. The current default example range is `0.7..1.0`, `count=10`.
- In mode 2, the TX vertical coil is now created as one opposite-wound RX-DD-style vertical DD pair on the `YZ` plane. Its internal gap follows `tx_vertical_mode2_pair_spacing_ratio * tx.region.outer_h_mm`, and its `X` follows `tx_dd_min_x + ratio * tx_dd_outer_x`. That means `1.0` lands on the RX-far edge of the underlying TX DD span.
- RX DD and TX vertical mode-2 internal DD links now use an RX-DD-style back-stub route instead of a central/nearest straight bar.
- The mode-2 TX vertical attachment routing now preserves the intended driven current direction: viewed from `+X`, the right `(+Y)` half is clockwise (`-X` local B) and the left `(-Y)` half is counterclockwise (`+X` local B).
- The TX DD TX-port sheet now uses diagonal pairing, replacing the nearest-start rectangle feed topology.
- The default `turn_count_max` range is now `2..3` for `tx_dd`, `tx_vertical`, and `rx_dd`, and runtime validation accepts up to `3`.
- The default example now fixes `coil_groups.tx_vertical.count_range` to `1`, and custom mode-2 specs that request a larger count clamp to realized `selected_count = 1`.
- FR4 subtraction is now split by board role so TX `YZ` FR4 and RX `YZ` FR4 do not share the same copper-tool set.
- RX ferrite footprint resolution now uses only RX-board `YZ` coil bboxes, so TX vertical mode-2 `YZ` bboxes do not contaminate RX ferrite placement.
- As a mode-2 feasibility hotfix, legacy `Y`-side `tx_bridge_no_pierce` / `tx_bridge_right_y_margin_ok` guards are skipped on the `YZ` plane. Those guards remain `ZX`-only contracts for now.

## Breaking Changes / Migration
- Runtime now accepts only `spec_version == "0.2.17"`.
- The public spec no longer accepts `coil_placement.tx_vertical_plane`.
- `selected_parameters.tx_vertical_plane` is no longer an input field; it is now a realized output with values `"ZX" | "YZ"`.

## Public API / Interface Changes
- `SUPPORTED_SPEC_VERSION = "0.2.17"` is now the public version baseline.
- `selected_parameters` now includes `tx_vertical_layout_mode`, `tx_vertical_mode2_pair_spacing_ratio`, `tx_vertical_mode2_pair_spacing_mm`, and `tx_vertical_mode2_x_ratio_to_tx_dd_center`.
- AEDT design-variable export serializes `tx_vertical_layout_mode` as an integer and the new pair-spacing ratio / x-ratio as unitless floats.

## Validation & Tests
- Sampling registry, dataset owner paths, and replay paths were updated to include the three new sampled owners.
- Rejection of removed `coil_placement.tx_vertical_plane` plus `layout_mode -> realized plane` derivation are locked by pure-Python tests.
- Pure-Python tests were expanded for mode-2 TX vertical bridge helpers, ferrite filtering, and FR4 subtraction routing.
