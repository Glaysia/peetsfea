# peetsfea 0.2.19

Release Date: `2026-03-20`

## One-line Summary
- 0.2.19 is a stabilization release that syncs the `0.2.19` baseline and rewrites the TX/RX port contract, TX geometry modes, and sample/build fail-fast flow around the current implementation.

## Highlights
- Synced the runtime spec baseline, examples, fixtures, docs, and versioned run-output naming to `0.2.19`.
- `tx_vertical_orientation_mode` now supports only `0 = no tx_vertical` and `1 = ZX tx_vertical`. The experimental `YZ` mode is postponed and removed from the active path.
- When `tx_vertical_orientation_mode = 0`, the `tx_vertical` sampling owner is still recorded, but realized `selected_count` becomes `0`, and the finalized TX DD conductor set is tilted about `Y` to satisfy the TX-region top contract.
- TX/RX ports were rebuilt around semantic conductor-based assignments. The runtime captures the actual HFSS excitation names and maps them back to the logical `TX_TML` / `RX_TML` aliases.
- The geometry/build/EM stack was reorganized around `builders`, `rules`, and `steps`, with stricter PyAEDT false-return fail-fast behavior, frozen-TOML replay validation, and failed-artifact cleanup.
- `corner_mode`, TX DD 1-turn topology recovery, Korean example-spec comments, and pure-Python regression coverage were updated in the same release.

## Breaking Changes / Migration
- Runtime now accepts only `spec_version == "0.2.19"`.
- `coil_placement.tx_vertical_orientation_mode` is interpreted only as `0` or `1`. Older specs that assume `YZ` mode-2 are not currently supported.
- The public spec no longer accepts `coil_placement.tx_vertical_plane`.
- The realized `selected_parameters.tx_vertical_plane` is now effectively fixed to `"ZX"`.
- The public TX DD count contract is organized around `stacked_mode = 0/1`; older `count_mode` / `selected_count=2/4` explanations are no longer the active public contract.
- Removed or dead paths are rejected aggressively. Examples include `coil_placement.tx_vertical_layout_mode`, `coil_placement.tx_dd_top_clearance_ratio`, `coil_shape.inner_margin_x`, and `coil_shape.inner_margin_y`.

## Public API / Interface Changes
- `SUPPORTED_SPEC_VERSION = "0.2.19"` is the current public baseline.
- `coil_placement.tx_vertical_orientation_mode` now means:
  - `0`: disable `tx_vertical`
  - `1`: enable `ZX tx_vertical`
- The common TX DD top-offset owner is now `coil_placement.neo_tx_dd_top_offset_ratio`.
- Geometry metadata now includes:
  - `tx_dd_rotation_angle_deg`
  - `tx_dd_rotation_pivot_xyz`
  - `tx_dd_rotation_object_names`

## Pipeline / Runtime Notes
- `entry/sample.py` produces resolved TOMLs and batch `manifest.json` files from the default batch-profile series.
- `entry/build.py` replays that same batch-profile series into AEDT builds.
- `entry/sample_build.py` no longer generates new samples; it replays existing manifests in GUI-visible sequential order.
- Build-input TOMLs must freeze every sampled owner. Non-frozen replay input fails immediately.
- `stop_on_error=False` is no longer supported.
- On build failure, `.aedt`, `.aedt.lock`, `.aedtresults`, and optional metadata/manifest/zip artifacts are cleaned up.

## Geometry Notes
- TX DD, TX vertical, and RX DD now share a stricter fail-fast geometry path.
- When `tx_vertical_orientation_mode = 0`, the finalize stage rotates the TX DD objects about `Y` to realize the no-vertical mode.
- The active TX vertical path is currently `ZX` only.
- RX remains on the `YZ` plane.
- TX DD 1-turn geometry was repaired so the realized conductor topology stays closed.
- `corner_mode` keeps the public `0=sharp_90`, `1=blunt` contract.

## Port / EM Notes
- TX/RX ports now come from finalized explicit conductor ports.
- Geometry captures the explicit port names, and the runtime keeps using `TX_TML` / `RX_TML` as logical report aliases.
- If the EM validation gate is `hard_fail`, missing TX/RX conductor groups now fail immediately.

## Stabilization
- PyAEDT calls that return `False` now raise immediately through the fail-fast wrappers.
- Nullable/fallback-dependent runtime behavior was reduced, and contracts between selection/build/geometry/EM were tightened.
- Sample/build replay and cleanup behavior were reorganized to reduce stale-artifact contamination between runs.
- Regression coverage and pyright-based cleanup were expanded for geometry, ports, manifests, and selection flow.
