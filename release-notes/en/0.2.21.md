# peetsfea 0.2.21

Release Date: `2026-04-04`

## One-line Summary
- 0.2.21 is a batch-stability release that fixes TX ferrite ordering/cutout handling and restores best-effort batch replay in `entry/build.py`.

## Highlights
- Synced the public package/spec baseline, examples, fixtures, docs, and versioned run-output naming to `0.2.21`.
- TX ferrite creation now runs after finalize-time bridge/stub geometry is created, so ferrite cutouts see the finalized TX live object set instead of an earlier partial scene.
- Removed the TX ferrite pre-subtract positive-gap rejection that blocked builds even when ferrite subtract would validly cut around TX bridges or terminal copper.
- `entry/build.py` once again supports best-effort batch replay with `stop_on_error=False`; failed entries are logged and recorded as `False` while the batch continues.

## Breaking Changes / Migration
- Runtime now accepts only `spec_version == "0.2.21"`.
- Older `0.2.20` TOML files must be bumped to `0.2.21` before they will run under the current baseline.

## Public API / Interface Changes
- `SUPPORTED_SPEC_VERSION = "0.2.21"` is the current public baseline.
- Batch build entrypoints keep fail-fast semantics by default, but now explicitly support best-effort replay again when `stop_on_error=False`.

## Runtime / Debug Notes
- TX ferrite overlap cases that are legitimately resolvable by ferrite subtract no longer fail early at ferrite placement-time validation.
- When a batch worker still fails under `stop_on_error=False`, `entry/build.py` now logs the design id, TOML path, exception type, and traceback before continuing.
