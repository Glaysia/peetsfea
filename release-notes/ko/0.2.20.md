# peetsfea 0.2.20

Release Date: `2026-04-03`

## 한 줄 요약
- 0.2.20은 TX mode-0 direct bridge가 이미 `tx_region_dd` 상단을 넘은 경우 회전을 `0도`로 고정해 빌드를 계속 진행시키고, AEDT message manager 내용을 런타임 wrapper 계층에서 바로 읽어오게 한 안정화 릴리즈다.

## Highlights
- 공개 패키지/스펙 baseline, examples, fixtures, 문서, versioned run-output naming을 `0.2.20`으로 동기화했다.
- `tx_mode0_rotation`은 finalized TX mode-0 candidate point가 이미 `tx_region_dd.top_z` 위에 있어도 즉시 raise하지 않고 회전 각도를 `0`으로 고정한다.
- 저장소의 AEDT protocol/wrapper/proxy 계층에 `Desktop.GetMessages(project_name, design_name, level)`를 추가했고, 내부적으로 PyAEDT `odesktop.GetMessages(...)`를 사용한다.
- geometry teardown `finally`에서 AEDT message manager 내용을 로거에 남겨, `ValidateDesign` 실패나 release 경로 문제에서도 실제 AEDT 에러 문구를 로그로 볼 수 있게 했다.

## Breaking Changes / Migration
- 런타임은 이제 `spec_version == "0.2.20"`만 허용한다.
- 기존 `0.2.19` TOML은 `0.2.20`으로 올린 뒤 실행해야 한다.

## Public API / Interface Changes
- `SUPPORTED_SPEC_VERSION = "0.2.20"`이 현재 공개 baseline이다.
- 저장소 AEDT desktop wrapper에 아래 메서드가 추가됐다.
  - `Desktop.GetMessages(project_name, design_name, level)`

## Runtime / Debug Notes
- 예전에는 `tx_mode0_rotation` 단계에서 바로 중단되던 TX mode-0 설계가 이제 `0도` 회전으로 계속 진행되며, 이후 실제 geometry/design 검증에서 AEDT가 거부하면 그 시점의 message manager 내용을 로그로 남긴다.
- GUI만 봐야 알 수 있던 `Parts ... intersect`류 AEDT 메시지를 repository logger에서 직접 확인할 수 있다.

## Validation
- headless `entry/build.py` replay는 기존 `000007_d161_847f_0` TX mode-0 회전 실패를 넘겨 계속 진행한다.
- 이후 실패 설계는 AEDT message-manager 로그를 통해 GUI 없이도 원인 수집이 가능하다.
