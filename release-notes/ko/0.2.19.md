# peetsfea 0.2.19

Release Date: `2026-03-20`

## 한 줄 요약
- 0.2.19는 `0.2.19` baseline 동기화와 함께 TX/RX 포트 계약, TX geometry mode, sample/build fail-fast 흐름을 재정리한 안정화 릴리즈다.

## Highlights
- 런타임 지원 스펙 버전, examples, fixtures, 문서, versioned run output naming을 `0.2.19` 기준으로 동기화했다.
- `tx_vertical_orientation_mode`는 이제 `0 = no tx_vertical`, `1 = ZX tx_vertical`만 지원한다. 실험하던 `YZ` mode는 잠정 보류하고 active path에서 제거했다.
- `tx_vertical_orientation_mode = 0`일 때는 `tx_vertical`의 sampling owner는 유지하되 realized `selected_count`를 `0`으로 만들고, finalize 단계에서 TX DD 전체를 `Y`축 기준으로 기울여 TX region top 계약을 맞춘다.
- TX/RX 포트는 detached sheet 전제 대신 실제 conductor 기준 semantic port 계약으로 재구성했고, HFSS가 부여한 실제 excitation 이름을 runtime에서 캡처해 `TX_TML` / `RX_TML` logical alias에 연결한다.
- geometry/build/EM 계층을 `builders`, `rules`, `steps` 구조로 재정리하고, PyAEDT false-return fail-fast, frozen TOML replay, 실패 산출물 정리를 강화했다.
- `corner_mode`, TX DD 1-turn topology, example TOML 한글 주석, pure-Python 회귀 테스트 범위도 함께 정리했다.

## Breaking Changes / Migration
- 런타임은 이제 `spec_version == "0.2.19"`만 허용한다.
- `coil_placement.tx_vertical_orientation_mode`는 `0` 또는 `1`로만 해석된다. 예전 `YZ` mode-2 전제 spec은 현재 지원되지 않는다.
- 공개 스펙은 더 이상 `coil_placement.tx_vertical_plane`를 받지 않는다.
- realized `selected_parameters.tx_vertical_plane`는 현재 `"ZX"`로 고정된다.
- `tx_dd`의 공개 입력은 `stacked_mode = 0/1` 기준으로 정리됐고, 예전 `count_mode`/`selected_count=2/4` 중심 설명은 더 이상 active public contract가 아니다.
- 예전 이름과 dead path는 적극적으로 거부한다. 예를 들어 `coil_placement.tx_vertical_layout_mode`, `coil_placement.tx_dd_top_clearance_ratio`, `coil_shape.inner_margin_x`, `coil_shape.inner_margin_y`는 현재 지원 대상이 아니다.

## Public API / Interface Changes
- `SUPPORTED_SPEC_VERSION = "0.2.19"`이 현재 공개 버전이다.
- `coil_placement.tx_vertical_orientation_mode`의 공개 의미는 아래 두 값이다.
  - `0`: `tx_vertical` 비활성화
  - `1`: `ZX tx_vertical` 활성화
- common TX DD top offset path는 현재 `coil_placement.neo_tx_dd_top_offset_ratio`를 사용한다.
- geometry metadata에는 아래 회전 정보가 포함된다.
  - `tx_dd_rotation_angle_deg`
  - `tx_dd_rotation_pivot_xyz`
  - `tx_dd_rotation_object_names`

## Pipeline / Runtime Notes
- `entry/sample.py`는 batch profile 집합을 기준으로 resolved TOML과 batch `manifest.json`을 만든다.
- `entry/build.py`는 같은 batch profile 집합을 다시 순회하면서 manifest replay build를 수행한다.
- `entry/sample_build.py`는 새 sample 생성 없이 기존 manifest만 GUI-visible 순차 replay한다.
- build 입력 TOML은 sampled owner 전부가 frozen 상태여야 하며, non-frozen TOML은 즉시 실패한다.
- `stop_on_error=False`는 더 이상 지원되지 않는다.
- build 실패 시 `.aedt`, `.aedt.lock`, `.aedtresults`, optional metadata/manifest/zip 산출물을 정리한다.

## Geometry Notes
- TX DD / TX vertical / RX DD는 모두 fail-fast geometry 경로로 통합했다.
- `tx_vertical_orientation_mode = 0`이면 finalize 단계에서 TX DD 객체를 `Y`축 기준으로 회전시켜 no-vertical 배치를 만든다.
- TX vertical active path는 현재 `ZX`만 지원한다.
- RX는 계속 `YZ` plane을 기준으로 한다.
- TX DD 1-turn geometry는 실제 폐곡선 conductor topology를 유지하도록 복구했다.
- `corner_mode`는 `0=sharp_90`, `1=blunt` 의미로 유지된다.

## Port / EM Notes
- TX/RX 포트는 finalized conductor 기준 explicit port에서 올라온다.
- geometry 단계가 만든 explicit port 이름을 runtime이 semantic 역할로 캡처하고, report expression에서는 계속 `TX_TML` / `RX_TML` alias를 쓴다.
- EM pipeline validation gate가 `hard_fail`이면 TX/RX conductor group이 없을 때 즉시 실패한다.

## Stabilization
- PyAEDT 호출에서 `False`가 반환되면 즉시 raise하도록 fail-fast wrapper를 강화했다.
- runtime nullable/fallback 의존을 줄이고, selection/build/geometry/EM 사이의 계약을 더 명시적으로 고정했다.
- sample/build replay 경로와 cleanup 동작을 정리해 stale artifact 때문에 다음 build가 오염되는 경우를 줄였다.
- geometry/port/manifest/selection 회귀 테스트와 pyright 기준 정리를 함께 진행했다.
