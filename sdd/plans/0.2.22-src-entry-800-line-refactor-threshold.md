# 0.2.22 `src/` / `entry/` 800-Line Refactor Threshold

## Goal
- `src/`와 `entry/`의 oversized tracked Python 파일을 책임 경계 기준으로 분리하는 운영 기준을 SDD에 고정한다.
- 줄 수만 맞추는 기계적 분할이 아니라 ownership clarity, reviewability, SDD traceability를 높이는 리팩터링 기준을 만든다.
- 실제 분리 작업에서 새 tracked Python 파일과 대응 `sdd/code` 노트가 항상 같이 생기도록 한다.

## Scope
- 포함:
  - `src/`와 `entry/`의 tracked Python 파일
  - size-driven split refactor의 plan/code-note/document coupling 규칙
  - 현재 over-threshold backlog 기록
- 제외:
  - `tests/`의 line-count threshold 관리
  - mechanical split only 작업
  - public API behavior 변경 허용

## Decisions
- `src/`와 `entry/`의 tracked Python 파일이 800줄을 넘으면 strong split candidate로 본다.
- 이 기준은 hard cap이 아니라 architecture-aware strong guideline이다.
- 예외는 convenience나 임시 보류가 아니라 문서화된 ownership boundary 판단으로만 허용한다.
- size-driven split은 줄 수 맞추기가 아니라 responsibility boundary 기준으로 수행한다.
- size-driven split을 다른 에이전트가 병렬 구현할 수 있게 하려면 target source path별 `sdd/code/...md`를 코드보다 먼저 만든다.
- 분리로 새 tracked Python 파일이 생기면 같은 변경 안에 대응 `sdd/code/<repo-relative-path>.md`를 반드시 추가한다.
- 분할 후 원본 파일이 남으면 기존 `sdd/code/...md` 노트도 축소된 책임, 새 협력 관계, 새 change hazard에 맞게 갱신한다.
- 분리로 module boundary, ownership flow, layering이 바뀌면 관련 `sdd/plans/`, `sdd/architecture/`, `sdd/structure/` 문서를 같은 변경에서 함께 갱신한다.
- `tests/`는 ordinary SDD note coverage 대상이지만, 800-line split threshold 대상은 아니다.

## Implementation Rule
1. When substantively editing an over-threshold `src/` or `entry/` file, first evaluate whether the change should reduce size through a boundary-respecting split.
2. If the edit does not split immediately, leave or update a related plan note that explains the deferred boundary decision.
3. If the edit does split, keep external behavior stable by default and move responsibilities rather than inventing fallback paths or alternate behavior.
4. Add matching code notes for each new tracked Python file in the same change.
5. Update the original file note and any affected architecture/structure note before considering the split complete.
6. If the split will be parallelized, use the pre-created target code notes as the implementation contract and update them first when boundaries change.

## Acceptance
- SDD policy clearly states that the 800-line threshold applies to `src/` and `entry/`, not `tests/`.
- The threshold is described as a strong guideline, not a hard cap.
- The plan names exact target source files for each oversized-file split instead of describing only generic future work.
- The plan pre-creates implementation-facing code notes for the planned target files.
- The note explicitly requires same-change `sdd/code/...md` creation for new tracked Python files created by a split.
- The note explicitly requires updating the original file's code note after responsibility reduction.
- The initial backlog lists the six current over-threshold `src/` / `entry/` files.
