# 0.2.22 Type2 Single STEP Setup-Ready Pipeline

## Goal
- type2 파이프라인 팀의 다음 큰 변경을 SDD 기준점으로 고정한다.
- `examples/type2_fixed.toml`에서 파생되는 canonical artifact를 object-level multi-file STEP 집합이 아니라 single scene STEP 하나로 수렴시킨다.
- `notebooks/view_step_files.ipynb`는 fixed-path single STEP viewer로 단순화하고, registry/index selection UI를 future contract에서 제거한다.
- single scene STEP import 이후 `EmPipelineInput`, explicit port/boundary, analysis setup, `ValidateDesign()`까지 완료된 setup-ready state의 ownership은 runtime/entry/pipeline에 둔다. `notebooks/view_type2_hfss_import.ipynb`는 그 state를 호출/확인하는 thin manual notebook으로 유지한다.
- 이번 문서는 SDD-only 계획이다. Python source, notebook JSON, tests, runtime behavior는 이 문서 자체로 바꾸지 않는다.

## Ownership Boundary
- 형상 설계팀:
  - single scene STEP 내부 body 구성, 배치, geometry composition 책임
  - pipeline이 소비할 canonical geometry metadata shape 협업
- 파이프라인 팀:
  - single artifact path/ledger/notebook/public import contract 정의
  - HFSS import handoff, imported ownership partitioning, `EmPipelineInput`, port/boundary/analysis, `ValidateDesign()` 경계 책임
  - notebook UX를 single artifact 중심으로 단순화

## Decisions
- future canonical scene STEP path는 `run/step/type2/type2_scene.step`이다.
- `run/step/type2/type2_step_ledger.json`은 retained metadata handoff로 유지한다.
- ledger는 artifact count가 아니라 role/ownership/port/validation metadata의 canonical handoff다.
- future single artifact는 post-hoc preview merge가 아니라 canonical full-scene STEP다.
- `notebooks/view_step_files.ipynb`는 폐기하지 않고 fixed single STEP viewer로 유지한다.
- `notebooks/view_type2_hfss_import.ipynb`는 auto-solve owner가 아니라 runtime-owned setup-ready/manual-solve-ready state를 호출/확인하는 thin manual consumer다.
- setup-ready는 imported ownership partitioning, `EmPipelineInput`, explicit port/boundary/source/analysis, `ValidateDesign()`까지 완료된 상태를 뜻한다.

## Planned Handoff
1. `examples/type2_fixed.toml`이 type2 object registry와 canonical metadata를 확정한다.
2. 형상 설계팀이 canonical `type2_scene.step`를 만든다.
3. 파이프라인 팀은 single scene STEP path와 `type2_step_ledger.json`을 canonical handoff로 기록한다.
4. `view_step_files.ipynb`는 `type2_scene.step` fixed path만 refresh/show한다.
5. headless HFSS import는 single scene STEP를 import하고 imported names를 ledger metadata와 결합한다.
6. pipeline adapter가 imported ownership을 TX/RX conductor, dielectric, ferrite, guide-object, port candidates로 partition한다.
7. pipeline runtime이 `EmPipelineInput`을 조립하고 `run_em_pipeline()`과 `ValidateDesign()`를 실행 가능한 setup-ready state로 끝낸다.
8. `view_type2_hfss_import.ipynb`는 `.aedt`와 imported/setup ledger를 보여주고 runtime이 만든 상태를 수동으로 확인한다. setup-ready behavior 구현 책임은 notebook이 아니라 runtime/entry/pipeline에 있다.

## Acceptance
- active SDD 문서가 future canonical STEP를 `run/step/type2/type2_scene.step`로 일관되게 설명한다.
- active SDD 문서가 ledger를 retained metadata handoff로 유지한다고 일관되게 설명한다.
- `view_step_files.ipynb`는 future contract에서 fixed single STEP viewer로 설명된다.
- `view_type2_hfss_import.ipynb`는 future contract에서 runtime-owned setup-ready state를 호출/확인하는 thin manual notebook으로 설명된다.
- 이 변경은 docs-only scope로 기록되며 source/notebook/test 변경을 포함하지 않는다.
