# 0.2.22 Type2 Step Spec Split

## Goal
- Split `src/peetsfea/type2_step_spec.py` into a facade plus dedicated modeled/sampling helper modules without changing TOML parsing, candidate resolution, seeded sampling, or `tx_rect_void` rendering behavior.
- Keep `type2_step_spec.py` as the stable compatibility import path for existing type2 callers.

## Target Boundaries
- `src/peetsfea/type2_step_spec.py`
  - Facade only: shared dataclasses, generic table/range validation, constraint parsing, non-model parsing, and load orchestration.
  - Imports modeled parsing/render helpers and sampling helpers from the new modules.
- `src/peetsfea/type2_step_spec_modeled.py`
  - Modeled-object parsing for single-coil, plate-stack, and `tx_rect_void_columns` roles.
  - Role/owner/plane helpers and `tx_rect_void` TOML rendering bridge.
- `src/peetsfea/type2_step_spec_sampling.py`
  - Candidate-range extraction and deterministic seeded resolution helpers for modeled and non-model sampled fields.

## Implementation Rules
- Do not change public behavior, TOML schema, seeded determinism, or fail-fast semantics.
- Do not introduce fallback branches or alternate parsing paths.
- Keep the facade import surface stable for existing downstream modules and tests.

## Acceptance
- Existing modeled and sampling tests continue to pass through the facade import path.
- Loader and render paths remain deterministic for the same TOML and seed.
- The new modules each have matching `sdd/code/` notes.

## Result
- The facade keeps the compatibility role helpers and load orchestration.
- The requested modeled parsing, candidate resolution, seeded sampling, and `tx_rect_void` render bridge now live in the split modules.
