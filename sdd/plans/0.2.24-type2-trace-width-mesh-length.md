# 0.2.24 Type2 Trace Width Mesh Length

## Goal
- Replace post-import mesh fixed `MaxLength = 5mm` with a value derived from modeled trace width metadata.
- Preserve each supported modeled conductor family's trace width in `canonical_coordinates.trace_width_mm` at STEP/scene creation time.

## Contract
- Single-coil modeled entries write realized rect/void `trace_width_mm` into canonical coordinates.
- Plate-stack modeled entries write realized stripe `trace_height_z` as canonical `trace_width_mm`, because that conductor strip width controls mesh density in the YZ section.
- `tx_rect_void_columns` modeled entries write realized rect/void trace width into canonical coordinates when assembled for STEP export.
- Setup-ready mesh computes `MaxLength` from canonical trace widths:
  - `TxRx`: `sqrt(tx_trace_width_mm * rx_trace_width_mm) / 9.0`
  - `RxOnly`: `rx_trace_width_mm / 9.0`
- Missing, non-numeric, non-finite, or non-positive trace widths fail immediately. No fixed fallback mesh length remains.

## Validation
- Update setup-ready mesh tests to assert dynamic `MaxLength` payload and summary values.
- Add fail-fast coverage for missing or invalid `canonical_coordinates.trace_width_mm`.
- Update import/setup fixtures so imported ledgers preserve the canonical trace width metadata used by mesh setup.
