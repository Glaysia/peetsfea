# 0.2.22 Type2 PyAEDT STEP Import

## Goal
- `examples/type2_fixed.toml`에서 생성된 canonical single scene STEP artifact를 headless HFSS 세션으로 import하는 runtime path를 둔다.
- PyAEDT `0.25.1`의 `Modeler3D.import_3d_cad()` 계약과, 기존 type1-style region/radiation boundary helper 계약을 repository fail-fast wrapper 안에 고정하는 후속 구현 방향을 문서화한다.
- runtime manifest/build dispatch에는 아직 연결하지 않고 type2 import + radiation boundary setup-ready 가능성만 먼저 검증한다.
- 이 계획은 [[sdd/plans/0.2.22-type2-step-to-em-validate-pipeline]]의 4번 마일스톤인 type2 headless import + radiation boundary 단계다.
- 이 문서의 boundary 서술은 preparatory contract이며, 실제 Python runtime 변경은 후속 코드 변경에서 수행한다.

## Decisions
- smoke script는 `Hfss(project=None, design=..., non_graphical=True, new_desktop=True)`로 headless 세션을 만든다.
- import 전후 `modeler.object_names` 차이를 새 imported object ledger로 삼고, 빈 diff는 fail-fast 대상이다.
- type2 authoring input은 future boundary policy를 소유하고, public TOML field path는 아직 고정하지 않는다. export 단계는 그 값을 retained STEP ledger top-level `em_policy`로 보존하는 방향을 계약으로 둔다.
- import runtime은 후속 구현에서 STEP import/style/validation 성공 뒤 기존 type1-style boundary flow를 재사용하는 방향을 따른다:
  - absolute-offset region 1개 생성
  - region faces 6개 조회
  - 각 face에 radiation boundary 1개씩 지정
- imported ledger는 imported object names만이 아니라 boundary summary도 top-level metadata로 보존하는 방향을 계약으로 둔다.
- imported modeled exact-name contract는 copper/PCB body 외에 current single-coil scene의 exact sheet names `tx_port_sheet`, `rx_port_sheet`를 포함하는 방향으로 둔다.
- port sheets are reference-surface bodies for a later port-assignment patch; this plan does not claim that the import runtime already turns them into lumped ports.
- `.aedt` 출력은 `run/aedt/type2_step_import/type2_import.aedt` 아래에 저장하는 현재 unified runtime path를 기준으로 설명한다.
- wrapper는 PyAEDT `0.25.1` 로컬 시그니처만 노출하고 `input_file_unit` fallback/대체 경로를 추가하지 않는다.
- 이 단계는 geometry import-only가 아니라 type2 policy-owned radiation boundary까지 포함한 setup-ready import contract를 정의한다. full `EmPipelineInput` 조립과 EM solve 준비 전체는 후속 단계로 남긴다.
- radiation helper는 새 type2 전용 알고리즘을 도입하지 않고, 기존 type1 boundary helper contract를 재사용하는 방향을 우선 결정으로 둔다.
- 위 boundary flow와 imported ledger boundary summary는 계획된 runtime contract이며, 현재 코드가 이미 absolute-offset region 생성과 6-face radiation assignment를 수행한다고 해석하지 않는다.
- 현재 importer-side `import_time_policy` expectation은 known drift다. canonical docs는 `em_policy` 기준이며 notebook failure 설명도 그 mismatch까지만 포함한다.
- fail-fast 계약은 기존 boundary helper와 동일하게 유지한다:
  - `create_region` false return 즉시 실패
  - `get_object_faces` false return 즉시 실패
  - region face count가 6이 아니면 즉시 실패
  - `assign_radiation_boundary_to_faces` false return 즉시 실패

## Acceptance
- 이 문서 변경만으로는 Python/runtime/TOML을 바꾸지 않는다.
- 문서 수용 기준:
  - type2 import는 geometry-only smoke가 아니라 future radiation-boundary-inclusive setup-ready path로 설명된다.
  - radiation margin ownership이 type2 authoring input과 retained STEP ledger `em_policy` 쪽에 있다고 일관되게 설명된다.
  - imported ledger가 future boundary summary를 포함한다고 설명된다.
  - imported exact-name contract가 current single-coil scene의 exact sheet names `tx_port_sheet`, `rx_port_sheet`를 포함한다고 설명된다.
  - absolute-offset region + 6 face radiation assignment는 type1-style flow를 따르는 planned import runtime behavior로만 설명되고, already-implemented state로 서술되지 않는다.
  - helper 재사용과 fail-fast boundary contract가 기존 type1 boundary logic과 일치한다고 설명된다.
