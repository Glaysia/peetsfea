# 0.2.22 Type2 RX Single Coil

## Summary
- `rx_single_coil`은 type2 rect/void single-coil engine을 `tx_single_coil`과 공유한다.
- corner geometry의 canonical source는 [0.2.22-type2-single-coil-corner-relief](0.2.22-type2-single-coil-corner-relief.md)다.
- type1 runtime은 변경 대상이 아니다.

## Decisions
- RX는 `src/peetsfea/tx_rect_void.py`의 shared single-coil core를 사용한다.
- role differences는 `plane`, `placement_owner_id`, body-name prefix, object id에만 둔다.
- shared engine의 canonical corner는 TX와 동일하게 always-on blunt corner다.
- ledger/import contract는 `plane`, `placement_owner_id`, `start_point_plane_mm`, `end_point_plane_mm`를 유지한다.
- RX placement contract는 계속 `YZ` plane, `rx_region_max`, owner max-X flush다.
- RX는 shared engine을 쓰더라도 current public contract에서는 single-layer-only를 유지한다.
- RX single-coil contract is independent of whether the active product path contains a TX modeled object.
- TX enable/disable policy is owned by the active runtime/default-path plan, not by this RX geometry note.
- Active default-path TX removal is owned by [0.2.22-type2-rx-only-baseline](0.2.22-type2-rx-only-baseline.md).
- RX backing ferrite/PET_PSA/air full-fill contract is owned by [0.2.22-type2-rx-single-coil-full-backing](0.2.22-type2-rx-single-coil-full-backing.md).

## Tests
- parser/export tests must keep `rx_single_coil` geometry, placement, body names, terminal metadata, and underlay grouping stable.
- import/setup tests must verify RX single-coil handling without changing TX policy in this note.
- geometry regression은 shared TX/RX engine이 blunt corner, same-corner seed, endpoint, winding, placement, metadata bounds를 같이 보존하는지 증명해야 한다.
- future multilayer regression은 TX 확장이 들어와도 RX single-layer fail-fast가 유지되는지 검증해야 한다.
