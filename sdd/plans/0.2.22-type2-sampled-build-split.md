# 0.2.22 Type2 Sampled Build Split

## Summary
- active type2 operator flow를 `entry/sample.py -> entry/build.py` 2단계로 고정한다.
- sample 단계는 source TOML에서 frozen sampled TOML을 만들고, policy에 따라 per-design STEP artifacts도 함께 만들 수 있다.
- build 단계는 existing STEP ledger를 재사용하거나 missing STEP을 same-worker에서 만든 뒤 setup-ready AEDT build를 수행한다.
- notebook `hfss_sampled.ipynb`는 build owner가 아니라 finished artifact viewer로만 유지한다.

## Key Decisions
- sampled TOML top-level metadata table 이름은 `[sampled]`로 고정한다.
- sampled metadata는 `source_toml_path`, `seed`, `design_id`, `sampled_owner_paths`를 가진다.
- sampled owner canonical path는 `modeled_objects.<object_id>.<field>` 형식으로 고정한다.
- per-design artifact root는 `run/sampled/type2/<design_id>/`다.
- sample-side runtime constant는 `SEED_FIRST`, `SEED_N`, `SAMPLER_N`, `AEDT_BUILDER_N`, `MAKE_STEP_ON_SAMPLE`를 가진다.
- `SEED_N`은 generated design count이자 canonical seed span이며, 대상 seed는 `range(SEED_FIRST, SEED_FIRST + SEED_N)`로 고정한다.
- `SAMPLER_N`은 design count가 아니라 sampled TOML owner worker 수다. `MAKE_STEP_ON_SAMPLE=true`일 때만 STEP export도 같은 worker가 맡는다.
- `seed`는 provenance only이며, design/folder identity는 `sample_index + generated_hash4 + head_hash4 + retry_number` 조합으로 이동한다.
- canonical folder name / `design_id` format은 `s{sample_index:06d}_{generated_hash4}_{head_hash4}_{retry_number}`다.
- build는 sampled TOML이 아닌 raw source TOML을 받으면 즉시 실패한다.
- AEDT design variable은 sampled metadata가 가리키는 owner만 넣고, 값은 sampled TOML frozen range에서 읽는다.
- sample는 one worker = one sampled TOML + one STEP export contract로 동작하고, 모든 sample 완료 뒤 manifest를 기록한다.
- build는 manifest config의 `aedt_builder_n`만 읽고, entry별로 existing STEP reuse 또는 missing STEP generate 후 AEDT를 생성한다.
- sample manifest top-level shape는 JSON array가 아니라 `config` + `entries` object다.
- notebook sampled selection은 별도 folder list 없이 manifest `entries` order를 그대로 인덱스 SSOT로 쓴다.
- low-level helper `generate_type2_step.py`, `import_type2_step.py`, `setup_type2_step.py`는 유지하되 active operator surface에서는 한 단계 아래로 내린다.
- `src/peetsfea/type2_sampled.py`는 facade/orchestration 중심으로 유지하고 sampled owner/constraint resolution 코어는 `src/peetsfea/type2_sampled_sampling.py`로 분리한다.
- 분리 후에도 public import surface는 `peetsfea.type2_sampled`에서 유지하고, entry/runtime/tests는 기존 import 경로를 그대로 사용한다.

## Acceptance
- source TOML의 `count != 1` owner만 sampled metadata에 기록된다.
- sampled TOML generation과 STEP export는 같은 sample worker path에서 병렬 worker 수와 무관하게 deterministic하다.
- `MAKE_STEP_ON_SAMPLE=true` sample 실행 뒤 각 design directory는 `sampled.toml`, `type2_scene.step`, `type2_step_ledger.json`을 가지며 `.aedt`는 없다.
- `MAKE_STEP_ON_SAMPLE=false` sample 실행 뒤 각 design directory는 `sampled.toml`만 가진다.
- sample stdout은 시작, stage, 매 완료 건 progress, manifest write, done 요약을 기록한다.
- manifest `entries[i]`는 notebook `VIEW_INDEX=i`와 동일한 sampled design을 가리켜야 한다.
- build는 existing STEP ledger corruption을 HFSS 실행 전 fail-fast로 검증하고, truly missing STEP만 same-worker export로 보완한다.
- build caller는 design variables를 sampled metadata에서만 얻는다.
- setup-ready runtime은 caller-provided design variables를 save 전에 적용한다.
- notebook과 active docs는 `hfss_sampled.ipynb`, `sample.py`, `build.py`를 가리킨다.
