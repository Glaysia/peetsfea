# 0.2.22 Type2 STEP to EM Validate Pipeline

## Goal
- `0.2.22`의 활성 제품 방향을 `type2 only`로 고정한다.
- type2의 단일 authoring input은 [[sdd/plans/0.2.22-type2-toml-unification]]에서 정의하는 `examples/type2.toml`이다.
- `type2.toml`에서 non-model guide objects와 modeled objects를 함께 읽어 object-level STEP artifact, metadata ledger, headless HFSS import, 이후 EM validate 확장까지 이어지는 단일 노선을 만든다.
- 이번 문서는 SDD-only 계획이다. Python runtime, TOML schema, dataset/repro 계약, GUI validation은 이 문서 자체로 바꾸지 않는다.

## Scope
- 포함:
  - `examples/type2.toml` 기반 object registry handoff 계획
  - `[[non_model_objects]]`와 `[[modeled_objects]]`를 같은 type2 registry 안에서 다루는 계획
  - `tx_rect_void`를 `type2.toml`의 첫 `tx_single_coil` modeled object로 승격하는 계획
  - imported AEDT object ledger에서 이후 `EmPipelineInput`을 조립하는 방향
- 제외:
  - 제거된 split TOML 입력을 새 기능 SSOT로 계속 확장하는 문서화
  - real AEDT solve 실행, GUI-visible AEDT validation, fallback import mode
  - EM port/source 계약과 multi-coil role taxonomy 확정

## Decisions
- 제품 계획의 활성 목표는 `type2`이며, `type1` 관련 구현 잔존 여부는 현재 상태 설명일 뿐이다.
- type2 SSOT는 `examples/type2.toml`이다.
- `type2.toml`은 object registry를 가진다. 모든 object는 최소한 `object_id`, `role`, `material`, `model_state`, canonical creation coordinates를 가진다.
- generated STEP artifact와 metadata ledger는 `type2.toml`의 object registry에서 파생된다.
- 생성 시점 metadata가 canonical state다. AEDT import 뒤 geometry를 역산해 role, coordinates, terminal semantics를 복원하지 않는다.
- 첫 modeled object는 `role = "tx_single_coil"`인 `tx_rect_void` TX coil이다.
- `tx_rect_void` 구현은 내부 재사용 가능하지만, 새 type2 public input ownership은 `type2.toml`이 가진다.
- non-model baseline은 완료된 선행 실험이며, 그 내용은 `type2.toml`의 `[[non_model_objects]]`로 흡수한다.

## Milestones
1. Completed baseline: non-model STEP 생성 + 시각화 완료
   - 참조: [[sdd/plans/0.2.22-type2-build123d-non-model-step]]
   - 의미: object-registry 기반 STEP authoring 가능성을 확인했다.

2. Type2 TOML unification
   - 참조: [[sdd/plans/0.2.22-type2-toml-unification]]
   - 의미: non-model scene과 `tx_rect_void` modeled coil input을 `examples/type2.toml`로 단일화한다.

3. Type2 object-level STEP export
   - 의미: `type2.toml`에서 non-model guide objects와 `tx_single_coil` modeled object를 읽어 object-level STEP artifact와 metadata ledger를 생성한다.

4. Type2 headless import smoke
   - 의미: `type2.toml`에서 생성된 STEP artifact를 headless HFSS로 import하고, import diff를 metadata ledger에 결합한다.

5. Follow-up expansion: imported ledger -> EM validate
   - 의미: imported ledger에서 `EmPipelineInput`, `run_em_pipeline()`, `validate_pipeline()`, `ValidateDesign()` 확장으로 간다.

## Planned Handoff
1. `type2.toml` object registry가 object id, role, material, model_state, canonical creation coordinates를 확정한다.
2. Build123d export 단계가 object별 STEP artifact와 registry-aligned metadata를 남긴다.
3. Headless HFSS import 단계가 STEP별 import 전후 `modeler.object_names` diff를 검증하고 imported AEDT object name ledger를 만든다.
4. Prototype adapter가 metadata ledger와 imported names를 결합해 imported ledger entry를 만든다.
5. Post-prototype adapter가 ledger role을 기준으로 TX/RX conductors, dielectric, ferrite, non-model guide object, explicit port names를 `EmPipelineInput`으로 조립한다.
6. Existing EM pipeline이 radiation boundary, ports, sources, analysis setup, output variable report를 만든다.
7. `validate_pipeline()`와 `ValidateDesign()`가 repository/AEDT 양쪽 fail-fast validation을 수행한다.

## Next Adapter Contract
- 다음 구현은 `type2.toml` 기반 export/import smoke path를 만든다.
- 이 adapter의 입력은 아래 2개다:
  - `type2.toml`에서 파생된 modeled object metadata entry
  - modeled STEP import 결과의 `imported_object_names`
- 이 adapter의 출력은 single imported ledger entry이며 최소 필드는 아래와 같다:
  - `object_id`
  - `role`
  - `material`
  - `model_state`
  - `step_path`
  - `canonical_coordinates`
  - `terminal_metadata`
  - `imported_object_names`
- 이 adapter의 fail-fast 전제는 아래와 같다:
  - prototype 단계에서는 `tx_single_coil` modeled object가 정확히 하나여야 한다.
  - metadata `step_path`와 실제 import input STEP가 일치해야 한다.
  - `imported_object_names`는 비어 있지 않고 중복이 없어야 한다.
- 이 단계의 목적은 아직 `EmPipelineInput` 완성본을 만드는 것이 아니라, `type2.toml`-derived modeled object metadata와 imported runtime names를 하나의 imported ledger entry로 합치는 것이다.
- 이 단계에서 의도적으로 미결정으로 남기는 항목은 아래와 같다:
  - TX/RX conductor 분류
  - endpoint-to-port mapping
  - EM context 값
  - `tx_single_coil` 이후 role taxonomy 확장
