# 0.2.22 Type2 STEP to EM Validate Pipeline

## Goal
- `0.2.22`의 활성 제품 방향을 `type2 only`로 고정하고, SDD 계획도 그 기준으로 정렬한다.
- type2는 object registry를 SSOT로 삼아 geometry authoring, STEP artifact, headless HFSS import, 이후 EM validate 확장까지 이어지는 단일 노선을 가진다.
- 현재 확보된 상태는 [[sdd/plans/0.2.22-type2-build123d-non-model-step]]의 non-model STEP 생성 및 시각화 완료다.
- 다음 단계는 [[sdd/plans/0.2.22-type2-pyaedt-step-import]]의 non-model STEP headless import smoke이고, 그 다음 concrete modeled milestone은 [[sdd/plans/tx-rect-void-step-generator]]의 TX single-coil STEP prototype이다.
- 이번 문서는 SDD-only 계획이다. Python runtime, TOML schema, dataset/repro 계약, GUI validation은 이 문서 자체로 바꾸지 않는다.

## Scope
- 포함:
  - type2 object registry를 기준으로 modeled/non-model object artifact handoff를 정리하는 계획
  - non-model baseline -> headless import smoke -> modeled single-coil prototype -> 이후 modeled import/EM validate 확장 순서를 고정하는 계획
  - imported AEDT object ledger에서 `EmPipelineInput`을 조립하는 후속 adapter 방향
  - `run_em_pipeline()`, `validate_pipeline()`, AEDT `ValidateDesign()`까지 이어질 후속 검증 경계
- 제외:
  - `entry/sample.py`, `entry/build.py`, manifest runtime dispatch 구현
  - type2 TOML schema 확정 또는 spec version bump
  - real AEDT solve 실행, GUI-visible AEDT validation, fallback import mode
  - type1을 활성 제품 목표로 유지하는 문서화

## Decisions
- 제품 계획의 활성 목표는 `type2`이며, `type1` 관련 구현 잔존 여부는 현재 상태 설명일 뿐이다.
- type2 SSOT는 object registry다. modeled/non-model object 모두 최소한 `object_id`, `role`, `material`, `model_state`, `step_path`, canonical creation coordinates를 가진다.
- 생성 시점 metadata가 canonical state다. AEDT import 뒤 geometry를 역산해 역할이나 좌표를 복원하지 않는다.
- non-model baseline은 완료된 선행 마일스톤으로 취급하고, 새 구현 계획의 시작점은 그 산출물을 사용하는 headless import smoke다.
- 첫 modeled prototype은 범용 coil family가 아니라 `tx_rect_void` 기반의 single modeled TX coil STEP으로 고정한다.
- modeled prototype 단계에서는 EM port/source/solve를 넣지 않고, future terminal 후보를 위한 metadata만 계획 범위에 포함한다.
- `tx_rect_void` metadata JSON은 기존 export payload 위에 single-entry `modeled_objects` proto-contract를 추가하는 방향으로 고정한다.
- 모든 PyAEDT `False` return은 즉시 raise한다. fallback import, silent retry, GUI 대체 검증, best-effort continuation은 포함하지 않는다.

## Milestones
1. Completed baseline: non-model STEP 생성 + 시각화 완료
   - 참조: [[sdd/plans/0.2.22-type2-build123d-non-model-step]]
   - 의미: type2 object-registry 기반 STEP authoring 가능성과 artifact viewing baseline을 이미 확보했다.

2. Next smoke: non-model STEP headless import
   - 참조: [[sdd/plans/0.2.22-type2-pyaedt-step-import]]
   - 의미: 현재 non-model artifact를 기준으로 HFSS import 가능성과 fail-fast wrapper 계약을 검증한다.

3. First modeled milestone: TX single-coil STEP prototype
   - 참조: [[sdd/plans/tx-rect-void-step-generator]]
   - 의미: `tx_rect_void`를 type2 modeled object의 첫 concrete prototype으로 승격하고, modeled object metadata 계약을 구체화한다.

4. Follow-up expansion: modeled import -> EM validate
   - 의미: modeled object registry와 imported AEDT object ledger를 연결하고, 이후 `EmPipelineInput`, `run_em_pipeline()`, `validate_pipeline()`, `ValidateDesign()` 확장으로 간다.

## Planned Handoff
1. Type2 object registry가 object id, role, material, model_state, canonical creation coordinates를 확정한다.
2. Build123d export 단계가 object별 STEP artifact와 registry-aligned metadata를 남긴다.
3. Headless HFSS import 단계가 STEP별 import 전후 `modeler.object_names` diff를 검증하고 imported AEDT object name ledger를 만든다.
4. 후속 adapter가 ledger role을 기준으로 TX/RX conductors, dielectric, ferrite, non-model guide object, explicit port names를 `EmPipelineInput`으로 조립한다.
5. Existing EM pipeline이 radiation boundary, ports, sources, analysis setup, output variable report를 만든다.
6. `validate_pipeline()`와 `ValidateDesign()`가 repository/AEDT 양쪽 fail-fast validation을 수행한다.

## Next Adapter Contract
- 다음 구현은 modeled import smoke adapter를 만든다.
- 이 adapter의 입력은 아래 2개다:
  - `tx_rect_void` metadata JSON의 `modeled_objects[0]`
  - modeled STEP import 결과의 `imported_object_names`
- 이 adapter의 출력은 single imported ledger entry이며 최소 필드는 아래와 같다:
  - `object_id`
  - `role`
  - `material`
  - `model_state`
  - `step_path`
  - `canonical_coordinates`
  - `terminal_metadata`
  - `imported_object_names`
- 이 adapter의 fail-fast 전제는 아래와 같다:
  - `modeled_objects` 길이가 1이어야 한다.
  - `role`은 `tx_single_coil`이어야 한다.
  - metadata `step_path`와 실제 import input STEP가 일치해야 한다.
  - `imported_object_names`는 비어 있지 않고 중복이 없어야 한다.
- 이 단계의 목적은 아직 `EmPipelineInput` 완성본을 만드는 것이 아니라, modeled object metadata와 imported runtime names를 하나의 imported ledger entry로 합치는 것이다.
- 이 adapter 단계에서는 metadata의 `role`, coordinates, terminal meaning을 canonical source로 유지하고, imported runtime names만 HFSS import 결과에서 읽는다.
- 이 단계에서 의도적으로 미결정으로 남기는 항목은 아래와 같다:
  - TX/RX conductor 분류
  - endpoint-to-port mapping
  - EM context 값
  - `tx_single_coil` 이후 role taxonomy 확장
