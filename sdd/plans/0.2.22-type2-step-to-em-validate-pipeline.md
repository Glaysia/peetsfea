# 0.2.22 Type2 STEP to EM Validate Pipeline

## Goal
- `0.2.22`의 활성 제품 방향을 `type2 only`로 고정한다.
- type2의 단일 authoring input은 [[sdd/plans/0.2.22-type2-toml-unification]]에서 정의하는 `examples/type2_fixed.toml`이다.
- `type2_fixed.toml`에서 non-model guide objects와 modeled objects를 함께 읽어 canonical single scene STEP, metadata ledger, headless HFSS import, 이후 EM validate 확장까지 이어지는 단일 노선을 만든다.
- `type2_fixed.toml`의 top-level `[outputs]`도 active EM report/output-variable SSOT로 포함한다.
- 이번 문서는 SDD-only 계획이다. Python runtime, TOML schema, dataset/repro 계약, GUI validation은 이 문서 자체로 바꾸지 않는다.

## Scope
- 포함:
  - `examples/type2_fixed.toml` 기반 object registry handoff 계획
  - `[[non_model_objects]]`와 `[[modeled_objects]]`를 같은 type2 registry 안에서 다루는 계획
  - `tx_rect_void`를 `type2_fixed.toml`의 첫 `tx_single_coil` modeled object로 승격하는 계획
  - imported AEDT object ledger에서 이후 `EmPipelineInput`을 조립하는 방향
- 제외:
  - 제거된 split TOML 입력을 새 기능 SSOT로 계속 확장하는 문서화
  - real AEDT solve 실행, GUI-visible AEDT validation, fallback import mode
- import-only helper(`type2_modeled_import_adapter` 계열)에 plate-stack setup-ready/EM ownership을 추가하는 구현
  - multi-coil role taxonomy 확정

## Decisions
- 제품 계획의 활성 목표는 `type2`이며, `type1` 관련 구현 잔존 여부는 현재 상태 설명일 뿐이다.
- type2 SSOT는 `examples/type2_fixed.toml`이다.
- type2 SSOT는 geometry/object registry뿐 아니라 EM report/output-variable 계약도 소유한다.
- `type2_fixed.toml`은 object registry를 가진다. 모든 object는 최소한 `object_id`, `role`, `material`, `model_state`, canonical creation coordinates를 가진다.
- generated scene STEP와 metadata ledger는 `type2_fixed.toml`의 object registry에서 파생된다.
- future canonical scene STEP path는 `run/step/type2/type2_scene.step`이다.
- `run/step/type2/type2_step_ledger.json`은 artifact count와 무관하게 retained metadata handoff로 유지한다.
- retained metadata handoff에는 top-level `outputs`가 포함되며 `--ledger` replay도 export 시점 report contract를 그대로 재사용한다.
- 생성 시점 metadata가 canonical state다. AEDT import 뒤 geometry를 역산해 role, coordinates, terminal semantics를 복원하지 않는다.
- future modeled single-coil STEP contract keeps port sheets out of STEP and reconstructs `tx_port_sheet`, `rx_port_sheet` from metadata when needed.
- underlay contract details are superseded by [[sdd/plans/0.2.22-type2-underlay-region-footprint-tx-gap-rx-support]]. Current canonical exact-name participants are role-aware TX `tx_underlay_*` and RX `under_rx_*`.
- port sheets are not fused into copper and are not subtracted from PCB because they are not STEP bodies at all in the active contract.
- port-sheet geometry is defined by connecting the two terminal stubs of a coil: the sheet lies in the shared plane of the two stub bottom faces and uses one canonical bottom-square diagonal from each stub.
- 첫 modeled object는 `role = "tx_single_coil"`인 `tx_rect_void` TX coil이다.
- `tx_rect_void` 구현은 내부 재사용 가능하지만, 새 type2 public input ownership은 `type2_fixed.toml`이 가진다.
- non-model baseline은 완료된 선행 실험이며, 그 내용은 `type2_fixed.toml`의 `[[non_model_objects]]`로 흡수한다.
- `notebooks/view_step_files.ipynb`는 future contract에서 single scene STEP viewer이며 registry/index selection을 제거한다.
- `notebooks/hfss_sampled.ipynb`의 future 역할은 auto-solve owner가 아니라 runtime-owned setup-ready/manual-solve-ready state를 호출/확인하는 thin manual consumer다.

## Milestones
1. Completed baseline: non-model STEP 생성 + 시각화 완료
   - 참조: [[sdd/plans/0.2.22-type2-build123d-non-model-step]]
   - 의미: object-registry 기반 STEP authoring 가능성을 확인했다.

2. Type2 TOML unification
   - 참조: [[sdd/plans/0.2.22-type2-toml-unification]]
   - 의미: non-model scene과 `tx_rect_void` modeled coil input을 `examples/type2_fixed.toml`로 단일화한다.

3. Type2 single scene STEP export
   - 의미: `type2_fixed.toml`에서 non-model guide objects와 modeled objects를 읽어 canonical `type2_scene.step`와 metadata ledger를 생성한다. single-coil modeled body set은 PCB/copper를 포함하고, current underlay contract에서는 role-aware explicit underlay solids를 append한다. port sheet는 metadata-driven reconstruction surface다.

4. Type2 headless import + post-import mesh + radiation boundary
   - 의미: `type2_fixed.toml`에서 생성된 STEP artifact를 headless HFSS로 import하는 후속 구현 단계에서, imported ownership partition + imported ledger 직후 runtime-owned mesh assignment를 적용한다. type2 authoring input이 소유한 `radiation_margin_mm`와 reconstructed `tx_port_sheet` / `rx_port_sheet` metadata는 role-aware setup-ready facade로 handoff되어 radiation boundary + explicit ports + final save를 수행한다. role-aware underlay solids도 이 단계의 import contract에 포함되지만 mesh owner는 아니다. 이 계획은 exact LengthOp mesh contract, setup-ready branch boundary/port/save ownership, import diff와 boundary summary 결합 방향을 정의하지만 아직 구현 완료를 주장하지 않는다.

5. Follow-up expansion: imported ledger -> EM validate
   - 의미: imported ledger에서 `EmPipelineInput`, `run_em_pipeline()`, `validate_pipeline()`, `ValidateDesign()` 확장으로 간다.

## Planned Handoff
1. `type2_fixed.toml` object registry가 object id, role, material, model_state, canonical creation coordinates를 확정한다.
2. Build123d export 단계가 single scene STEP와 registry-aligned metadata ledger를 남긴다.
3. Headless HFSS import 단계가 single scene STEP import 전후 `modeler.object_names` diff를 검증하고 imported AEDT object name ledger를 만든다.
4. Prototype adapter가 metadata ledger와 imported names를 결합해 imported ledger entry를 만든다.
5. modeled import contract는 PCB/copper body names와 role-aware underlay exact solids를 보존한다. `tx_port_sheet`, `rx_port_sheet`는 runtime reconstruction ownership으로만 보존한다.
6. 같은 import 단계에서 runtime/pipeline ownership으로 `MeshSetup.AssignLengthOp(...)`를 적용한다. current exact contract는 role-pair resolver가 선택한 TX/RX conductor 세트다: single-coil pair는 TX `tx_copper_l0 | tx_copper_stack`, RX `rx_copper_l0`; plate-stack pair는 role prefix 기반 copper family(`*_copper_wall_t*`, `*_copper_coil_t*`, `*_bridge_s*`, `*_stub_*`)를 mesh 대상으로 쓴다. `RefineInside=False`, `Enabled=True`, `RestrictElem=False`, `NumMaxElem="1000"`, `RestrictLength=True`, `MaxLength="5mm"`다. underlay solids는 mesh 대상이 아니다.
7. 같은 import 단계는 type2 policy-owned `radiation_margin_mm`와 reconstructed stub-port metadata를 setup-ready facade에 전달하고, setup-ready branch가 absolute-offset region 생성, 6-face radiation assignment, explicit port assignment, final save, boundary summary 기록까지 수행하는 방향으로 계획한다.
8. Post-prototype adapter가 ledger role을 기준으로 TX/RX conductors, dielectric, ferrite, non-model guide object, explicit port names를 `EmPipelineInput`으로 조립한다.
9. Existing EM pipeline이 ports, sources, analysis setup, output variable report를 만든다. type2 setup-ready는 hardcoded report가 아니라 retained step ledger top-level `outputs`를 사용한다. radiation boundary logic은 type2 import path에서 먼저 재사용/적용하는 방향을 우선 계약으로 둔다.
10. `validate_pipeline()`와 `ValidateDesign()`가 repository/AEDT 양쪽 fail-fast validation을 수행한다.
11. `notebooks/hfss_sampled.ipynb`는 runtime이 만든 setup-ready state를 호출/확인하는 thin manual notebook으로 수렴한다.

## Next Adapter Contract
- 다음 구현은 `type2_fixed.toml` 기반 single scene export/import setup-ready path를 만든다.
- import-only helper(`type2_modeled_import_adapter` 계열)는 계속 modeled metadata + imported names 결합 ownership을 가진다.
- 이 adapter의 입력은 아래 2개다:
  - `type2_fixed.toml`에서 파생된 modeled object metadata entry
  - single scene STEP import 결과의 `imported_object_names`
- import runtime은 adapter 이전 단계에서 type2 authoring input이 소유한 `radiation_margin_mm`와 `terminal_metadata.kind = "stub_port"`를 retained STEP ledger로 전달하고, setup-ready facade가 type1-style boundary helper + explicit port helper + save contract를 재사용하는 방향으로 확장한다. 이 서술은 preparatory contract이며, 현재 runtime이 이미 전 단계를 완료했다고 주장하지 않는다.
- 현재 importer가 `import_time_policy`를 기대하는 구현은 known drift다. 이 계획 문서의 canonical 계약은 `em_policy` 기준이며 runtime correction은 후속 코드 작업이다.
- import runtime은 same exact-name contract에 PCB/copper와 role-aware underlay solids를 포함시키는 방향으로 확장한다. `tx_port_sheet`, `rx_port_sheet`는 reconstructed metadata surfaces로 남긴다.
- same retained ledger는 top-level `outputs`를 통해 report name, solution, sweep, output-variable expressions를 보존한다.
- 이 adapter의 출력은 single imported ledger entry이며 최소 필드는 아래와 같다:
  - `object_id`
  - `role`
  - `material`
  - `model_state`
  - `step_path`
  - `canonical_coordinates`
  - `terminal_metadata`
  - `imported_object_names`
- imported ledger top-level에는 setup-ready branch 결과를 반영한 boundary summary를 추가하는 방향을 계약으로 둔다:
  - `type`
  - `offset_type`
  - `offset_value`
  - `region_name`
  - `face_count`
- import runtime은 imported ledger 작성 직후 아래 post-import mesh contract를 setup-ready baseline으로 적용하는 방향을 계약으로 둔다:
  - module: `MeshSetup`
  - operation: `AssignLengthOp`
  - operation name: `Length1`
  - objects: role-pair resolver가 선택한 TX/RX conductor set (plate-stack pair는 role prefix copper family 전체)
  - `RefineInside=False`
  - `Enabled=True`
  - `RestrictElem=False`
  - `NumMaxElem="1000"`
  - `RestrictLength=True`
  - `MaxLength="5mm"`
- boundary summary는 planned imported ledger metadata이며, 구현 전까지는 required future shape로만 다룬다.
- 이 adapter의 fail-fast 전제는 아래와 같다:
  - prototype 단계에서는 `tx_single_coil` modeled object가 정확히 하나여야 한다.
  - metadata `step_path`와 실제 import input STEP가 일치해야 한다.
  - `imported_object_names`는 비어 있지 않고 중복이 없어야 한다.
- setup-ready boundary/port/save 단계에서는 아래도 fail-fast 전제로 둔다:
  - type2 authoring policy 또는 retained STEP ledger `em_policy.radiation_margin_mm`가 없거나 유효하지 않으면 즉시 실패
  - region create 결과가 `False`면 즉시 실패
  - region face count가 정확히 6이 아니면 즉시 실패
  - radiation assignment 중 하나라도 `False`를 반환하면 즉시 실패
  - reconstructed port-sheet 기반 explicit port assignment 중 하나라도 `False`를 반환하면 즉시 실패
  - final save 결과가 실패하면 즉시 실패
- mesh 단계에서는 아래도 fail-fast 전제로 둔다:
  - `MeshSetup` module lookup이 실패하면 즉시 실패
  - `AssignLengthOp` 결과가 `False`면 즉시 실패
  - selected TX/RX conductor set 구성에 필요한 exact names가 누락되면 즉시 실패
  - underlay exact names가 mesh target set에 섞이면 즉시 실패
- 이 단계의 목적은 아직 `EmPipelineInput` 완성본을 만드는 것이 아니라, `type2_fixed.toml`-derived modeled object metadata와 imported runtime names를 하나의 imported ledger entry로 합치는 것이다.
- 이 단계에서 의도적으로 미결정으로 남기는 항목은 아래와 같다:
- TX/RX conductor 분류
- endpoint-to-port mapping
- imported port-sheet ownership에서 explicit lumped-port assignment를 만드는 adapter
- EM context 값
- `tx_single_coil` 이후 role taxonomy 확장

## Acceptance
- SDD references resolve through the plan, architecture, diagram, and code-note indices.
- 수용 기준:
  - 새 type2 계획은 `examples/type2_fixed.toml`을 단일 public authoring input으로 설명한다.
  - 제거된 split TOML 입력은 새 기능 SSOT가 아니다.
- `tx_rect_void`는 standalone workflow가 아니라 `type2_fixed.toml`의 첫 modeled object role로 설명된다.
- future canonical scene STEP는 `run/step/type2/type2_scene.step`로 설명된다.
- post-import mesh 단계는 import 직후, setup-ready 이전에 위치한 runtime-owned exact contract로 설명된다.
- modeled body set은 PCB/copper와 role-aware underlay solids를 exact-name contract로 설명하고, `tx_port_sheet` / `rx_port_sheet`는 reconstructed metadata surfaces로 설명된다.
- plate-stack import metadata는 sentinel `{"kind": "none"}`가 아니라 `terminal_metadata.kind = "stub_port"`로 설명된다.
- active plate-stack branch는 role-aware setup-ready facade에서 radiation boundary + explicit
  ports + final save를 수행하고, 이후 full EM chain으로 이어지는 것으로 설명된다. import-only helper는 geometry inspection ownership으로만 유지된다.
- `hfss_sampled.ipynb`는 runtime-owned setup-ready state를 호출/확인하는 thin manual notebook으로 설명된다.
