# 0.2.24 Type2 TX Outer Removal

## Goal
- Remove the derived `tx_outer_single_coil` active path while keeping the explicit `tx_inner_single_coil` geometry-only TX context.
- Keep active Type2 examples, sampling, STEP export, import, and setup-ready on `tx_inner_single_coil` plus `rx_single_coil`.
- Preserve `tx_region`, `tx_inner_region`, and `tx_inner_actual_region` guide/actual-region behavior; do not reintroduce full TX EM activation.

## Decisions
- `tx_outer_rect_void_coil` must no longer be appended by the loader, exported to STEP, listed in modeled ledgers, imported as optional geometry, accepted by setup-ready role gates, or exposed as a sampled owner.
- TOML fields `tx_outer_terminal_path` and `tx_outer_x_position_ratio` are removed from active examples and must fail fast if declared on `tx_inner_single_coil`.
- `tx_outer_region` was originally retained as a non-modeled guide for the removed outer TX coil; active Type2 export must now omit `tx_outer_region` as well as `tx_outer_actual_region`.
- Dormant helper code for rejecting or diagnosing legacy `tx_outer_single_coil` artifacts may remain if deleting it would widen the change unnecessarily, but no active STEP/ledger/test path may emit `tx_outer_region`.
- Existing artifacts containing `tx_outer_single_coil` are not migrated or tolerated in the active build/setup path; reject them with actionable errors.
- Legacy `type1` paths remain untouched.

## Coordination Rules
- Workers are not alone in the codebase. Preserve edits by other agents and do not revert or reformat unrelated files.
- Do not edit legacy `type1` files, notebooks, or unassigned worker files unless a compile/test failure proves a direct dependency. If cross-boundary edits are needed, report the exact file and reason.
- No fallback behavior: unsupported `tx_outer` state must raise immediately.
- Markdown-only output does not complete a worker slot; each worker must either change assigned Python/test files or report a concrete implementation blocker.
