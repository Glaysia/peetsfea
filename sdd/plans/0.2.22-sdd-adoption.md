# 0.2.22 SDD Adoption

## Goal
- `0.2.22+` 이후 변경부터 코드와 설계 문서를 같이 움직이게 만든다.
- 옵시디언에서 바로 따라갈 수 있는 Markdown 상대경로 링크 중심의 SDD 볼트를 부트스트랩한다.
- 의미 기반 계층 링크 정책으로 전역 허브 반복 링크를 줄인다.

## Scope
- 포함:
  - `SDD.md`
  - `AGENTS.md`
  - `sdd/*-index.md`
  - [source-note](../templates/source-note.md)
  - [plan-note](../templates/plan-note.md)
  - [architecture-note](../templates/architecture-note.md)
- 제외:
  - 레포 전체 기존 코드의 일괄 백필
  - 자동 검사기 추가
  - 기존 `docs/`, `notes/`, release notes 구조 변경

## Decisions
- forward-only 도입이다.
- 기본 적용 범위는 `src/`, `entry/`, `tests/`의 추적되는 Python 코드다.
- 대응 코드 문서 경로는 `sdd/code/<repo-relative-code-path>.md`로 고정한다.
- 신규 기능과 큰 리팩터링은 계획 문서를 먼저 만들거나 같은 변경 안에서 같이 만든다.
- Markdown 링크는 직접 계획, 협력 코드, 테스트, 구체적 아키텍처/다이어그램에만 둔다.
- 전역 정책/허브 링크를 모든 노트의 `Links` 섹션에 반복하지 않는다.

## Acceptance
- `0.2.22+` SDD 정책이 루트에서 바로 보인다.
- 에이전트 규칙과 문서 정책이 서로 충돌하지 않는다.
- 허브, 템플릿, 예시 노트가 있어서 다음 변경부터 바로 대량 생산이 가능하다.
