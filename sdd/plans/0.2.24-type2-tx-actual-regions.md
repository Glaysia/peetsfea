# 0.2.24 Type2 TX Actual Regions

## Goal
- Add visible non-modeled `tx_inner_actual_region` and `tx_outer_actual_region` bodies that represent the resolved coil design outer boxes.
- Resolve actual regions before modeled coil STEP construction from guide-region coordinates, modeled coil usage ratios, selected stack values, and seed.
- Keep modeled coil placement ownership unchanged: coils still use their guide regions and existing usage ratios.

## Decisions
- `tx_inner_region` and `tx_outer_region` remain guide regions.
- `tx_inner_actual_region` is derived from `tx_inner_region` plus the `tx_inner_single_coil` spec and seed.
- `tx_outer_actual_region` is derived from `tx_outer_region` only when a real outer TX coil spec exists; do not emit a placeholder copied from the guide region.
- Actual regions are non-model, vacuum, STEP-visible, and ledger-retained. They do not create ports, sources, reports, mesh targets, or active EM setup changes.
- Actual-region XY size is the selected resolved design outer size, not the smaller modeled material/body bbox:
  - `actual_x = guide.size_x * selected outer_x_usage_ratio`
  - `actual_y = guide.size_y * selected outer_y_usage_ratio`
- Actual-region XY placement mirrors the current single-coil placement policy: centered in the guide owner for `tx_inner_single_coil`; future outer TX placement must document its guide-owner anchoring before enabling `tx_outer_actual_region`.
- Actual-region Z may use the realized physical coil stack/body height, but canonical X/Y must remain the design `outer_x_mm`/`outer_y_mm` box. Physical body bounds may be stored only as diagnostic provenance.

## Sub-Agent Work Packages
- Actual resolver package:
  - Own non-model actual-region resolution in `src/peetsfea/type2_non_model_scene.py`.
  - Add creation-time provenance registries and STEP-visible groups for `tx_inner_actual_region` and future `tx_outer_actual_region`.
  - Keep fail-fast behavior for missing modeled specs, invalid selected ratios, and unsupported placeholder outer actuals.
- Single-coil sizing package:
  - Own helper extraction in `src/peetsfea/type2_single_coil_scene.py`.
  - Expose deterministic helper data for both resolved design outer box and physical modeled body bounds without building the full STEP scene.
  - Preserve current placement owner behavior and avoid applying usage ratios twice.
- Ledger/import contract package:
  - Own ledger typing and validation surfaces for actual-region provenance.
  - Add `tx_inner_actual_region` and `tx_outer_actual_region` non-model member entry types without changing modeled-object ledger shape.
- Test package:
  - Own type2 export tests proving actual regions appear in ledger and STEP, match the resolved design outer box, and move/resize when guide ratios or usage ratios change.

## Acceptance
- Fixed type2 export emits `tx_inner_actual_region` after `tx_inner_region` and before `tx_outer_region`.
- The fixed example `tx_inner_actual_region` XY canonical size is `28.0 x 168.0`, derived from `tx_inner_region.size_x=56.0`, `tx_inner_region.size_y=280.0`, `outer_x_usage_ratio=0.5`, and `outer_y_usage_ratio=0.6`.
- The fixed example `tx_inner_actual_region` XY minimum is `(14.0, -84.0)`, centered inside `tx_inner_region`.
- The modeled TX inner material/body bbox is contained inside `tx_inner_actual_region` in X/Y, but is not equal to the actual-region canonical bounds.
- Changing `outer_x_usage_ratio` or `outer_y_usage_ratio` changes `tx_inner_actual_region` while leaving `tx_inner_region` unchanged.
- No `tx_outer_actual_region` is emitted until an outer TX coil modeled source exists.
- Pure-Python tests cover ledger member ids, provenance, STEP labels, deterministic sizing, and no active EM setup changes.
