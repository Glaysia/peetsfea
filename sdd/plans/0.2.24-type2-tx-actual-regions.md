# 0.2.24 Type2 TX Actual Regions

## Goal
- Add visible non-modeled `tx_inner_actual_region` and `tx_outer_actual_region` bodies that represent the resolved visible coil body boxes.
- Resolve actual regions before modeled coil STEP construction from guide-region coordinates, modeled coil usage ratios, selected stack values, and seed.
- Keep modeled coil placement ownership unchanged: coils still use their guide regions and existing usage ratios; TX inner X placement is lower-X wall-side anchored rather than sampled by `x_position_ratio`.

## Decisions
- `tx_inner_region` and `tx_outer_region` remain guide regions.
- `tx_inner_actual_region` is derived from `tx_inner_region` plus the `tx_inner_single_coil` spec and seed.
- `tx_outer_actual_region` is derived from `tx_outer_region` only when a real outer TX coil spec exists; do not emit a placeholder copied from the guide region.
- `tx_outer_actual_region` is an axis-aligned non-model box around the tilted outer coil's resolved design outer box, per the 2026-05-03 implementation decision.
- Actual regions are non-model, vacuum, STEP-visible, and ledger-retained. They do not create ports, sources, reports, mesh targets, or active EM setup changes.
- Actual-region XY size is the selected visible physical body bbox after realizing the owner-scaled coil geometry.
- Actual-region XY placement mirrors the active single-coil placement policy: `tx_inner_single_coil` is lower-X wall-side anchored inside `tx_inner_region` and remains centered in Y; outer TX uses the same virtual sloped-owner placement as `tx_outer_single_coil` and stores the resulting world-space AABB.
- Actual-region Z uses the realized physical coil stack/body height; physical body bounds are stored as canonical provenance and match actual-region bounds for TX inner.

## Sub-Agent Work Packages
- Actual resolver package:
  - Own non-model actual-region resolution in `src/peetsfea/type2_non_model_scene.py`.
  - Add creation-time provenance registries and STEP-visible groups for `tx_inner_actual_region` and future `tx_outer_actual_region`.
  - Keep fail-fast behavior for missing modeled specs, invalid selected ratios, and unsupported placeholder outer actuals.
- Single-coil sizing package:
  - Own helper extraction in `src/peetsfea/type2_single_coil_scene.py`.
  - Expose deterministic helper data for the resolved visible physical box without building the full STEP scene.
  - Preserve current placement owner behavior and avoid applying usage ratios twice.
- Ledger/import contract package:
  - Own ledger typing and validation surfaces for actual-region provenance.
  - Add `tx_inner_actual_region` and `tx_outer_actual_region` non-model member entry types without changing modeled-object ledger shape.
- Test package:
  - Own type2 export tests proving actual regions appear in ledger and STEP, match the resolved visible physical body box, and move/resize when guide ratios or usage ratios change.

## Acceptance
- Fixed type2 export emits `tx_inner_actual_region` after `tx_inner_region` and before `tx_outer_region`.
- The fixed example `tx_inner_actual_region` XY canonical size is `262.2566037735849 x 625.8566037735849`, derived from the realized visible body bbox after owner-scaled `outer_x_usage_ratio=0.5` and `outer_y_usage_ratio=0.6`.
- The fixed example `tx_inner_actual_region` XY minimum is `(0.0, -312.92830188679244)`: lower-X wall-side anchored at the `tx_inner_region` minimum X and centered inside `tx_inner_region` in Y.
- The modeled TX inner material/body bbox matches `tx_inner_actual_region` in X/Y so imported geometry touches the selected wall and stays Y-centered.
- Changing `outer_x_usage_ratio` changes `tx_inner_actual_region` width while leaving its minimum X fixed at the lower-X wall side; changing `outer_y_usage_ratio` changes its Y size while preserving Y centering. Both leave `tx_inner_region` unchanged.
- Fixed type2 export emits `tx_outer_actual_region` after `tx_outer_region` when the derived `tx_outer_single_coil` companion exists.
- `tx_outer_actual_region` is not equal to the full `tx_outer_region` guide placeholder and contains the outer modeled body AABB within tolerance.
- Pure-Python tests cover ledger member ids, provenance, STEP labels, deterministic sizing, and no active EM setup changes.
