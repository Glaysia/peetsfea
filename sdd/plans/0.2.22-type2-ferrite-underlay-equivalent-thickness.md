# 0.2.22 Type2 Ferrite Underlay Equivalent Thickness

## Goal
- active `type2` underlay ferrite family에서 `underlay_repeat_count`를 repeated exported body count가 아니라 effective thickness multiplier로 재해석한다.
- TX floor underlay, TX wall-parallel stack, RX underlay 모두 같은 effective tri-layer contract로 정리한다.
- TOML/sampling 입력 surface는 유지하면서 scene export/import exact-name contract만 collapsed single-`u0` trio 기준으로 바꾼다.

## Scope
- 포함:
  - `type2_step_scene.py` underlay geometry emission rewrite
  - expected body names/count rewrite
  - TX/RX export regression updates
  - import/setup-ready pure-Python helper and expectation updates
  - docs/SDD note updates
- 제외:
  - `tx_rect_void` copper/PCB geometry
  - port-sheet semantics
  - legacy `type1`
  - new TOML fields

## Decisions
- `underlay_repeat_count = N > 0`이면 each active underlay family is exported as one effective tri-layer set only:
  - `*_ferrite_u0`
  - `*_pet_psa_u0`
  - `*_air_u0`
- effective layer thicknesses are:
  - ferrite: `N * 0.20 mm`
  - PET_PSA: `N * 0.15 mm`
  - air: `N * 0.02 mm`
- fit validation remains based on total thickness `N * (0.20 + 0.15 + 0.02)`.
- TX floor anchor remains ferrite top face at `modeled_min_z - underlay_gap_mm`.
- TX wall material order remains `wall -> coil = ferrite -> PET_PSA -> air`.
- RX material order remains `-X -> +X = air -> PET_PSA -> ferrite`.
- `expected_exported_body_names`/`count` now encode collapsed `u0` body sets instead of `u0..u{N-1}` expansion.

## Acceptance
- `repeat_count=0` exports no underlay bodies.
- `repeat_count=2` and `8` export exactly one `u0` tri-layer set per active family with multiplied thickness.
- import/style/setup-ready tests continue to treat underlay as non-mesh solids with existing materials.
- docs explicitly describe `underlay_repeat_count` as effective thickness multiplier for type2 ferrite family.
