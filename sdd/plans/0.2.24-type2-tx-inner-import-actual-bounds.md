# 0.2.24 Type2 TX Inner Import Actual Bounds

## Summary
- Fix TxRx setup import failure where `tx_inner_single_coil` physical modeled bounds are smaller than the centered TX inner design/actual region.
- Preserve the existing placement owner: modeled `tx_inner_single_coil` remains owned by `tx_inner_region`.
- Use `tx_inner_actual_region` provenance as the import-time design bounds contract instead of recentering the physical modeled bbox directly inside `tx_inner_region`.

## Implementation Boundaries
- Export provenance must record `tx_inner_actual_region.tx_actual_region.physical_modeled_body_bounds` from the physical modeled body bbox, while canonical `tx_inner_actual_region` bounds remain the design outer box.
- Import core must pass the `tx_inner_actual_region` member to TX inner bounds validation.
- Import style validation must require:
  - actual/design bounds are centered in Y, contained in X/Y, and top-aligned in Z inside `tx_inner_region`;
  - modeled physical bounds are contained inside actual/design bounds;
  - recorded physical provenance matches the modeled ledger entry bounds;
  - source guide and modeled source IDs match the owner and modeled object.
- The validation remains fail-fast. No fallback owner inference, recentering, snapping, or alternate behavior is allowed.
