# 0.2.22 Type2 RX-Only Baseline

## Summary
- Active type2 default is one modeled object: RX `rx_single_coil`.
- This is not a TX disable mode. Existing TX modeled paths are removed from the active default so future TX work can start from a new explicit coil contract.
- RX geometry ownership stays with the existing type2 rect/void single-coil engine.

## Decisions
- Active examples contain `rx_rect_void_coil` / `rx_single_coil` only.
- `tx_region` may remain as a non-modeled spatial reservation, but it must not create active TX geometry, ports, sources, outputs, or sampled owners.
- Setup-ready active branch is RX-only: import, mesh, radiation boundary, one RX lumped port, RX source phase, analysis/report, validation, `ValidateDesign`, and final save.
- RX-only port naming uses boundary `1` and excitation `1_T1`.
- RX-only mesh target is exactly `rx_copper_l0`.
- Active outputs contain RX self terms only. No active output expression may reference `TX_TML`, mutual coupling, S21, TX Q/R/X, or efficiency/FOM terms.
- Existing TX plate-stack/array implementation is not the active operator path.

## Implementation Notes
- Do not represent missing TX with nullable runtime state, empty fallback objects, fake ports, or degraded substitutes.
- Pair-oriented historical helpers may stay only where explicitly retained as component regression coverage; active examples/sample/build/setup-ready must assert RX-only.
- Future TX work must add a new explicit role/schema rather than reusing old TX plate-stack as a fallback default.

## Verification
- `tests/type2/test_generate_type2_step.py` covers active RX-only fixed example export/ledger body contracts.
- `tests/type2/test_sample_type2_entry.py` and `tests/type2/test_build_type2_entry.py` cover RX-only sampled owner paths, manifest roles, and build handoff.
- `tests/backend_em/test_type2_step_setup_ready.py` covers RX-only mesh, port, EM input, source/report, validation, and save behavior.
- `tests/backend_em/test_em_pipeline_sources.py` covers RX-only source phase behavior.
