# Type2 Exported Body Bounds Import Validation

## Goal
- Fix the headless Type2 AEDT build failure where STEP import succeeds but `tx_inner_rect_void_coil` is skipped before `.aedt` save.
- Keep `canonical_coordinates` as the semantic modeled-body/placement contract used by actual-region, mesh, and port logic.
- Add a separate ledger contract for the full exported/imported body union bbox so passive underlay and void-stack bodies can be validated without corrupting semantic coordinates.

## Decisions
- The ledger schema moves from `type2.step_ledger.v2` to `type2.step_ledger.v3`.
- Every modeled object entry must include `exported_body_canonical_coordinates`.
- Import-time AEDT bbox drift validation compares imported body union bounds against `exported_body_canonical_coordinates`, not `canonical_coordinates`.
- Existing `terminal_metadata.kind = "single_coil_port_v1"` remains the only active port-sheet coordinate source.
- Default `entry/build.py` batch output must not report success when every failed design was only recorded in `type2_build_skipped.json`; skipped designs raise after the ledger is written.
- Direct headless AEDT repro showed a second import failure: build123d scene compounds plus empty STEP `MANIFOLD_SOLID_BREP` names arrive in AEDT as `SOLID*`. The AEDT scene export contract must therefore flatten modeled ferrite-family groups into leaf bodies and stamp each STEP BREP name from the ledger/export label order before import.

## Implementation Boundaries
- Export-side modeled entry builders populate `exported_body_canonical_coordinates` from the exact top-level STEP body children that are declared in `expected_exported_body_names`.
- Final AEDT scene STEP export emits leaf bodies only; group names in `expected_exported_body_groups` are post-import grouping contracts, not exported STEP bodies.
- After build123d writes the STEP file, export verifies the number of blank `MANIFOLD_SOLID_BREP` records matches the leaf scene-body order and replaces each blank name with the exact leaf label. Mismatch fails before ledger hashing.
- Import-side ledger validation requires and validates both coordinate blocks for modeled entries.
- Import core uses the exported-body coordinate block only for post-`import_3d_cad` object bbox validation; style, owner/actual-region validation, mesh, and port assignment keep consuming the existing semantic contract.
- Tests must include a TX inner case where `canonical_coordinates` excludes passive underlay/void-stack depth while `exported_body_canonical_coordinates` includes it.

## Task C Export Runtime Contract
- `type2_step_export.py` enriches every modeled scene-data return path owned by the export assembly before metadata or ledger serialization, including direct single-coil export, active assembly export, `tv_aluminum_plate`, plate stacks, active single-coil roles, and `tx_rect_void_columns`.
- The exported-body coordinate block is derived from the exact labels in `expected_exported_body_names`; missing or duplicate labels fail before ledger emission.
- `test_generate_type2_step.py` asserts schema v3 and includes a TX inner passive-underlay plus void-stack case where semantic `canonical_coordinates` stays narrower than `exported_body_canonical_coordinates`.

## Task D Import Runtime Contract
- `type2_step_import_core._assert_imported_object_bounds_match_ledger()` reads `exported_body_canonical_coordinates.outer_bounds_min_xyz` and `.outer_bounds_size_xyz` from the validated modeled ledger entry.
- The drift assertion remains before runtime port-sheet `create_polyline` because it still runs before modeled import styling and adapter entry creation.
- `test_type2_port_sheet_runtime_contract.py` carries both coordinate blocks and uses deliberately different semantic/exported bounds so a regression back to `canonical_coordinates` changes test behavior.

## Task E Backend EM Fixtures
- `test_type2_step_import_pipeline.py` fake ledgers emit schema `type2.step_ledger.v3`, include `exported_body_canonical_coordinates`, and seed fake imported bboxes from exported-body coordinates.
- `test_type2_step_setup_ready.py` TxRx fake ledgers use the same v3 exported-body bbox source.
- TX inner import coverage keeps semantic `canonical_coordinates` coil-only while exported-body bounds include underlay and void-stack passive bodies.
- Exported-body drift coverage shifts every imported exported body and asserts failure before port-sheet creation.
