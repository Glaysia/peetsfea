# Type2 Range Owner Descriptions

## Summary
- Move sampled/range owner descriptions out of notebook-local Python dictionaries and into the type2 TOML range owner tables.
- Keep descriptions as metadata: they document public owner meaning but do not change geometry, sampling, replay, or design-variable state.
- Require complete descriptions for official examples and notebook display, while preserving parser compatibility for existing TOML fixtures without descriptions.

## Contract
- A range owner table may contain `range` and optional `description` keys.
- When present, `description` must be a non-empty string.
- Official examples must include `description` for every owner returned by type2 range-owner discovery, including fixed `count=1` public range owners.
- Notebook display must read descriptions from the selected TOML and fail if an owner description is missing.

## Work Packages
- Parser: allow optional range table descriptions and reject malformed descriptions without binding them into `RangeSpec`.
- Tools/tests: expose a lightweight `type2_range_owner_descriptions(path)` helper and test full coverage against official examples.
- Examples: add descriptions beside every range owner in `examples/type2_sweep.toml` and `examples/type2_fixed.toml`.
- Notebook: remove `_OWNER_DESCRIPTIONS` and use TOML-backed descriptions for selected sampled parameter display.
