# Type2 TxRx TX Inner EM Activation

## Goal
- Enable active `TxRx` EM setup for modeled `tx_inner_single_coil` plus the existing RX coil.
- Keep `RxOnly` supported as the single-terminal mode.
- Keep generic TX modeled roles dormant unless a later change gives them explicit import, port, mesh, and output support.

## Scope
- `TxRx` uses `tx_inner_single_coil` as the only active TX role for this change.
- TX port geometry comes from STEP ledger `terminal_metadata`, using the same metadata shape already used by RX.
- Runtime terminal names are explicit: TX uses `TX_TML`, RX uses `RX_TML`.
- AEDT sheet names are deterministic: `tx_inner_port_sheet` and `rx_port_sheet`.
- TX inner conductor names are deterministic and role-specific so mesh assignment and port setup can fail fast on missing objects.
- Report variables include TX self, RX self, mutual coupling, S/Y/Z, efficiency, and FOM expressions for `TxRx`.

## Non-Scope
- Do not activate generic `tx_single_coil`, `tx_plate_stack`, or `tx_rect_void_columns`.
- Do not add fallback behavior when TX ledger data, port sheet geometry, or output variables are missing.
- Do not change STEP exporter fail-fast behavior.
- Do not run GUI AEDT validation unless the user explicitly asks for GUI mode.

## Work Distribution
- Worker A owns output spec mode and example/test surface:
  `src/peetsfea/spec/outputs.py`, `examples/type2_sweep.toml`, `examples/type2_fixed.toml`, and focused spec import tests.
- Worker B owns TX import styling and port assignment:
  `src/peetsfea/backend/pyaedt/type2_step_import_style.py`, `src/peetsfea/backend/pyaedt/type2_step_port_assignment.py`, and focused port/import tests.
- Worker C owns EM input and mesh assignment:
  `src/peetsfea/backend/pyaedt/type2_step_em_input.py`, `src/peetsfea/backend/pyaedt/type2_step_post_import_mesh.py`, and focused payload/mesh tests.
- Worker D owns setup-ready orchestration and integration tests:
  `src/peetsfea/backend/pyaedt/type2_step_setup_ready.py`, `tests/backend_em/test_type2_step_setup_ready.py`, and STEP/spec integration assertions.

## Invariants
- `RxOnly` must still reject TX-only report variables and require exactly one RX terminal path.
- `TxRx` must require both `TX_TML` and `RX_TML` variables to be internally consistent with assigned ports.
- Unsupported output modes and variable names must raise immediately.
- Unsupported TX modeled roles must raise before AEDT setup rather than being ignored.
- Missing or malformed terminal metadata must raise with object id, role, and source path context.
