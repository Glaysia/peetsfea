# Type2 STEP Export Scene Data Reuse

## Intent
- Reduce `run-type2-sample-with-step` wall time by removing duplicate modeled geometry construction during STEP export validation.
- Preserve fail-fast ledger/body/terminal metadata validation; do not skip validation or add fallback paths.
- Keep exported STEP and ledger artifacts wire-compatible.

## Decisions
- `export_type2_step_artifacts()` remains the public export boundary.
- The first pass through modeled specs remains the only pass that builds modeled scene shapes for active single-coil bodies.
- Post-export terminal contract validation must compare ledger metadata against the scene data already built in the same export call.
- Tests must guard that the post-export validation path does not call `build_modeled_scene_data()` again for single-coil metadata checks.
- `entry/sample.py` may gain explicit CLI overrides for seed range and worker count so operators can run small diagnostic samples without editing code.

## Invariants
- STEP export still raises if `bd.export_step()` returns non-`True`.
- Body name/count/group validation remains active.
- Terminal metadata drift still fails in the same export call.
- Sample defaults remain `SEED_FIRST=0`, `SEED_N=12`, `SAMPLER_N=12`, and `--build-step` remains opt-in.
- No AEDT GUI or EM solve is introduced by this change.

## Work Slots
- Slot A: refactor `src/peetsfea/type2_step_export.py` to pass first-pass modeled scene data into terminal contract validation.
- Slot B: add focused `tests/type2/test_generate_type2_step.py` coverage proving validation reuses first-pass scene data and still catches drift.
- Slot C: add bounded `entry/sample.py` CLI overrides for seed range and worker count without changing defaults.
- Slot D: add `tests/type2/test_sample_type2_entry.py` coverage for the new sample CLI overrides and manifest config.
