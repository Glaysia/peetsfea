# Phase 0 방향 설정: 여러 안 (초안)

## 목적
Phase 0은 "무엇을 먼저 고정할지"를 결정하는 단계다. TOML SSOT, 결정론, pyaedt 격리, 문서화/LLM 협업의 전제를 만족하면서 MVP 범위를 정한다.

---

## 안 A: Spec 최소화 + 결정론 우선
**핵심 아이디어**: 최소 스키마와 seed 기반 결정론을 먼저 고정하고, 형상 템플릿은 2~3개로 제한.

- **범위**
  - `spec_version`, `design`, `parameters`, `components`만 정의
  - 샘플링 정책(고정 RNG)과 seed 요구사항 확정
  - 2~3개 기본 형상(예: solenoid, toroid, core E)
- **결과물**
  - Spec 문서 초안 + 예시 TOML 2개
  - preflight 체크리스트 초안
  - 결정론 테스트(순수 파이썬)
- **장점**
  - 위험 최소화, 빠른 합의
  - SSOT 원칙과 결정론을 초기에 고정
- **리스크**
  - 형상 다양성/문서화가 늦어짐
- **권장 상황**
  - 방향이 불명확하고 빠른 합의가 필요할 때

---

## 안 B: 형상 카탈로그 우선
**핵심 아이디어**: 다양한 형상 템플릿 목록과 파라미터 표준을 먼저 정리해 LLM 협업 기반을 확보.

- **범위**
  - 형상 타입 8~12개 후보 정의
  - 각 템플릿별 파라미터 목록/범위 표준화
  - 문서화 구조와 예시 TOML 집중 작성
- **결과물**
  - Shape Catalog 초안(문서)
  - 파라미터 공통 표준(단위/이름 규칙)
  - 예시 TOML 5개 이상
- **장점**
  - LLM과 협업 설계 가능성이 빠르게 열림
  - 사용자 가시성이 높음
- **리스크**
  - spec/결정론/샘플링은 뒤로 밀림
- **권장 상황**
  - 초기부터 설계 다양성이 중요한 경우

---

## 안 C: 파라미터/샘플링 엔진 우선
**핵심 아이디어**: 결정론 파라미터 해석/샘플링 엔진을 먼저 만들고, 형상은 1~2개만 시험.

- **범위**
  - 파라미터 타입/범위/분포 스키마 확정
  - seed 기반 sampler 구현 및 기록 포맷 결정
  - 간단한 형상 1~2개에만 적용
- **결과물**
  - 파라미터 해석기 + 결정론 테스트
  - resolved parameter 포맷 정의
  - constraints 검증 규칙 초안
- **장점**
  - 재현성/데이터셋 생성 기반이 빨리 완성됨
- **리스크**
  - 실제 형상 다양성 및 문서화가 늦음
- **권장 상황**
  - 데이터셋 생성/재현성이 핵심인 경우

---

## 안 D: 코드 생성 파이프라인 우선
**핵심 아이디어**: TOML -> 중간모델 -> Python 코드 생성 경로를 먼저 검증.

- **범위**
  - 최소 스키마 + AST/IR 정의
  - 코드 템플릿/생성 규칙 확정
  - backend 인터페이스 초안
- **결과물**
  - 코드 생성기 PoC
  - backend 호출 인터페이스 문서
  - 최소 예시 1개 실행
- **장점**
  - "명세에서 코드 생성"의 핵심 가설을 빠르게 검증
- **리스크**
  - 파라미터/샘플링/문서화는 후순위
- **권장 상황**
  - 메타프로그래밍 경로가 가장 불확실할 때

---

## 안 E: Pyaedt 연동 PoC 우선
**핵심 아이디어**: pyaedt 호출과 headless 환경에서의 제약을 먼저 확인.

- **범위**
  - 1~2개 형상만 pyaedt로 직접 생성
  - headless 실행 가능성, 버전 이슈 확인
  - backend 모듈 구조 점검
- **결과물**
  - pyaedt 연동 체크리스트
  - 실패/제약 사항 목록
  - backend 인터페이스 초안
- **장점**
  - 기술 리스크를 초기에 제거
- **리스크**
  - spec/결정론/문서화가 밀림
- **권장 상황**
  - pyaedt 환경 안정성이 불확실할 때

---

## 선택 기준 제안
- **재현성 중심**이면 안 A 또는 C가 적합.
- **LLM 협업/설계 다양성**이 우선이면 안 B.
- **메타프로그래밍의 가능성 검증**이 우선이면 안 D.
- **pyaedt 환경 리스크 확인**이 우선이면 안 E.

---

## 공통 Phase 0 산출물 체크리스트
어떤 안을 선택하더라도 아래는 최소 확보 권장:
- spec 버전 정책 초안(버전 규칙, 호환 정책)
- seed/결정론 원칙 문서화
- MVP 형상 목록 (수량과 범위 합의)
- preflight에서 지원/비지원 정의 초안
- `examples/`에 TOML 예시 2개 이상
