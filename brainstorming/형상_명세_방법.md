# 형상 명세 방법 (초안)

## 1) 목표 요약
- 대부분의 변압기/무선전력전송(WPT) 형상을 **코드가 아닌 TOML 명세**로 표현한다.
- TOML 명세 + 랜덤 시드(seed) + 버전이 **하나의 설계에 일대일로 대응**하고, 동일 조건이면 완전 재현 가능해야 한다.
- TOML을 SSOT로 두고, 이에 대응하는 **파이썬 코드(Pyaedt 호출)를 자동 생성**한다.
- 많은 형상 템플릿을 미리 준비해 **문서화 + LLM 협업 설계**가 가능해야 한다.

## 2) 설계 원칙 (AGENTS 요약)
- TOML spec이 단일 진실(SSOT)이며 코드와 1:1 대응.
- 결정론: 동일 spec + seed + 버전 + pyaedt/aedt 버전에서 동일 결과.
- 랜덤/샘플링은 반드시 명시적 seed를 입력받음.
- 명시적 기본값과 문서화. 숨겨진 implicit default 금지.
- Pyaedt 의존 코드는 backend로 격리하고 대체 가능해야 함.
- 실행 환경 설정은 TOML에 넣지 말고 Python 코드에 둔다.
- Preflight validation에서 지원/비지원 기능을 명시적으로 보고.
- 스펙 파라미터 추가 시 버전 업데이트 고려.

## 3) 형상 범위 초안 (카탈로그 대상)
- 코일: solenoid, pancake, spiral, litz bundle, planar trace.
- 코어: E/U/I, toroid, PQ, pot, C-core, gap 포함.
- 실드/보빈/하우징: ferrite shield, aluminum shield, bobbin, casing.
- 배열/반복: 다층/다중 코일, array placement, symmetry/array.
- 보조 요소: air region, boundary, port/terminal 지정.

## 4) TOML 구조 개요 (MVP 방향)
- 최상위: `spec_version`, `design`, `components`, `parameters`, `sampling`, `backend`.
- **component**: 형상 템플릿 타입 + 위치/자세 + 파라미터 참조.
- **parameters**: 타입/단위/범위/분포/기본값 명시.
- **sampling**: seed + 방법 + 제약/의존성.
- **backend**: pyaedt 모델링에 필요한 최소 스위치만(실행 환경은 Python).

### 예시 구조 (스케치)
```toml
spec_version = "0.1.0"

[design]
name = "tx_rx_basic"
units = "mm"
seed = 1234

[parameters.coil_turns]
type = "int"
default = 10
min = 5
max = 20

[parameters.coil_radius]
type = "float"
default = 25.0
min = 10.0
max = 60.0
unit = "mm"

[[components]]
type = "coil.solenoid"
id = "tx_coil"
position = { x = 0, y = 0, z = 0 }
orientation = { axis = "z", angle_deg = 0 }
params = { turns = "parameters.coil_turns", radius = "parameters.coil_radius" }

[[components]]
type = "core.toroid"
id = "core1"
position = { x = 0, y = 0, z = -5 }
orientation = { axis = "z", angle_deg = 0 }
params = { inner_d = 20.0, outer_d = 60.0, height = 10.0, gap = 1.0 }
```

## 5) 파라미터 명세 규칙
- 타입: `int | float | bool | enum | string`.
- 단위: 기본 단위를 `design.units`로 정의하고, 개별 파라미터에 명시 가능.
- 범위: `min/max` 또는 `choices`(enum). 샘플링은 명시적 분포만 허용.
- 의존성: 참조는 `parameters.xxx` 경로만 허용, 단순 산술만 지원(명시적으로 제한).
- 기본값: 모든 파라미터에 `default` 명시.
- 제약식: 별도 `constraints` 섹션에서 명시하고 validation에 사용.

## 6) 결정론/샘플링 설계
- seed는 design에서 반드시 명시하거나, 명령행/실행 코드에서 강제 입력.
- 샘플링 알고리즘은 고정(예: numpy RNG) + 버전 기록.
- TOML + seed → **resolved parameter set**을 만들고, 결과를 저장(재현성 증빙).
- 파라미터 스윕/샘플링은 `sampling` 섹션에서 일관되게 정의.

## 7) 코드 생성(메타프로그래밍) 전략
- TOML → AST/중간 모델 → Python 코드 생성(혹은 코드 템플릿).
- 생성 코드의 역할: **pyaedt backend 호출에 필요한 객체 생성/조립**만 수행.
- backend 레이어는 형상 템플릿을 함수/클래스로 제공(교체 가능).
- 생성 코드와 backend 간 **1:1 매핑**이 유지되도록 템플릿을 고정.

## 8) 문서화/LLM 협업 설계
- 각 형상 템플릿마다:
  - id, 설명, 파라미터 목록/범위, 사용 예시 TOML.
  - 지원되는 backend/pyaedt 버전.
  - 제약/주의사항.
- `docs/`에 “Spec Reference”와 “Shape Catalog” 분리.
- LLM이 접근 가능한 요약 텍스트 + 상세 문서를 병행.

## 9) 단계별 로드맵 (세부 계획)
### Phase 0: 방향 정리
- MVP에 포함할 형상 타입 5~8개 선정.
- 결정론 기준과 샘플링 정책 확정.
- 스펙 버전 및 backward-compat policy 초안 작성.

### Phase 1: Spec 최소 스키마
- `spec_version`, `design`, `parameters`, `components` 정의.
- 표준 톰l 스키마 규칙 및 validation 규칙 문서화.
- `preflight` 검사기: 지원/비지원 항목 명시.

### Phase 2: 파라미터/샘플링 엔진
- seed 기반 deterministic sampler 구현.
- `parameters` → `resolved` 변환 로직 + 저장 포맷 정의.
- 제약 검증(범위/의존성/충돌) 구현.

### Phase 3: 코드 생성기
- TOML → 중간 모델 → python 코드 템플릿 설계.
- backend 인터페이스 확정(형상 생성 함수 시그니처).
- 생성 코드는 최소 기능만 수행하도록 제한.

### Phase 4: 형상 카탈로그 확대
- 코일/코어/실드 등 주요 템플릿 추가.
- 각 템플릿 문서화 + TOML 예시 작성.
- 예시 기반 테스트 케이스(결정론 테스트 포함).

### Phase 5: 통합/검증
- spec + seed → 모델 생성 → pyaedt로 실제 형상 생성.
- 최소 1~2개 integration test (선택).
- 결과 재현성 체크(버전 고정 조건 포함).

## 10) 오픈 이슈/결정 필요 항목
- 표현식 허용 범위(수식/조건/참조) 어디까지 제한할지.
- 좌표계/변환(회전, local frame) 표현 규칙.
- 배열/복제/패턴(예: coil array) 문법 설계.
- 결과물의 저장 포맷(geometry metadata, resolved params).
- spec 버전 업 시 호환 정책(경고/자동 변환 여부).

## 11) 지금 당장 시작할 실무 체크리스트
- MVP 형상 목록 확정(5~8개).
- `examples/`에 TOML 스케치 2~3개 작성.
- `spec` 문서 구조 템플릿 만들기.
- seed + sampler 결정(모듈/버전 고정).
- backend 인터페이스 초안 작성.
